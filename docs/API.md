# API 약속 (화면과 서버가 주고받는 것)

> **저장 위치:** `docs/API.md`

> **사용 방법**
> 1. 오늘은 **오늘 만든 기능 하나의 항목만** 씁니다. 전체 API는 다음 차시 이후에 채웁니다. 개발자1과 개발자2가 **구현하기 전에 같이 읽고 약속**하는 문서이기도 합니다.
> 2. 항목의 **입력·출력·실패 응답**은 `backlog.md`의 **인수 조건**과 `first-feature.md` 2절에서 가져옵니다. 인수 조건에 없는 응답을 새로 만들지 않습니다.
> 3. 필드 이름·상태값은 `DATA-MODEL.md`와 **똑같이** 씁니다.
> 4. 이 문서는 **공유 파일**입니다. PM만 고치고, 바꿀 일이 있으면 PR 댓글로 요청합니다. 개발자1과 개발자2가 합의한 약속을 PM이 옮겨 적습니다.
> 5. 모르는 것은 `미정`으로 씁니다. 임의로 정하지 않습니다.
> 6. `>`로 시작하는 안내 문장은 지워도 됩니다.

- 최종 수정일: 2026-11-03
- 근거: `backlog.md` US-01, `first-feature.md` 2절. `DATA-MODEL.md`는 아직 비어 있다.
- 상태: **제안(합의 전)**. 개발자1(서버)·개발자2(화면)가 같이 읽고 합의하면 PM이 이 표시를 지운다.

## 공통 규칙
| 항목 | 내용 |
| --- | --- |
| 응답 형식 | 제안(합의 전): JSON |
| 오류 응답 형식 | 미정. 인수 조건상 "해당 항목과 거절 사유"를 화면에 보여 줄 수 있어야 한다 |
| 인증·권한 | 미정. MVP는 회원가입 없이 모의 계정으로 구분하는데, 계정을 요청에 어떻게 싣는지 아직 정하지 않았다 |

## 항목 1: 준비 건 만들기 (기능 ID: F-01 / 스토리: US-01)

| 항목 | 내용 |
| --- | --- |
| 요청 (경로·방식) | 제안(합의 전): `POST` 방식, 파일이 있어 `multipart/form-data`. 경로 이름은 미정 |
| 입력 | 지원 유형(F-6-1만), 상황 설명(1~1,000자, 공백·줄바꿈만은 안 됨), PDF 파일 1~5개(각 10MB = 10,485,760바이트 이하). 표시 언어는 오늘 범위 밖. 필드 이름은 DATA-MODEL 확정 후 맞춤 |
| 출력 (성공) | 만들어진 준비 건 1개: 준비 건 ID, 상태 `준비중`, 소유자, 생성 일시 |
| 실패 응답 | 준비 건을 만들지 않고 거절한 항목과 사유를 돌려준다: PDF 아님(확장자 또는 파일 시그니처), 10MB 초과, 파일 0개·6개 이상, 빈 상황 설명, 1,000자 초과, F-6-1 외 유형. HTTP 상태 코드는 미정 |
| 권한 (누가 못 하나) | 다른 이용자·로그인 안 한 사용자의 조회 403/401은 `first-feature.md`에서 오늘 범위 밖 |
| 바뀌는 상태 | (시작) → 준비중 |
| 관련 인수 조건 | `first-feature.md` 2절 1~4번 |
| 화면이 쓰는 곳 | 준비 건 생성, 이용자 준비 건 목록 (`DESIGN.md` 화면 이름 확정 전) |

### 입력·출력 예시
```
요청: 미정 (필드 이름 합의 후)
응답(성공): 미정
응답(실패): 미정
```
