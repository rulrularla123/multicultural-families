# UI 디자인 방향

> **저장 위치:** `docs/DESIGN.md`

> **사용 방법**
> 1. 화면을 만들기 **전에** 화면이 어떤 느낌과 규칙으로 만들어질지 팀이 합의하는 문서입니다. **개발자2가 씁니다**(결정은 팀).
> 2. 색·간격은 **토큰 표**에 한 번만 정하고, 화면에서는 값을 직접 쓰지 않고 이 이름을 씁니다.
> 3. 화면 목록은 PRD의 **기능 ID(`F-xx`)와 연결**합니다. 기능에 없는 화면이나 화면 없는 기능이 없어야 합니다.
> 4. **선택은 팀이 합니다.** Claude는 화면 목록과 기능의 어긋남, 빠진 상태(빈 화면·오류·로딩)를 찾아 주기만 합니다.
> 5. 오늘은 **색 3개, 간격 1개, 화면 목록**까지만 해도 됩니다. 나머지는 `미정`으로 남깁니다.
> 6. `>`로 시작하는 안내 문장은 지워도 됩니다.

- 확정일: (팀 합의 필요)
- 상태: 초안. 토큰 값, 분위기, 화면 구성은 팀 합의 전이다.

## 방향 한 줄
- 분위기: 차분하고 읽기 쉬운 행정 안내. 장식보다 현재 상태와 다음 할 일이 먼저 보이게 한다.
- 참고 서비스 (캡처 없이 이름만): 미정
- 반응형: 미정 (모바일 화면 폭 기준: 미정)

## 토큰 (값은 화면 코드에서 이름으로 씁니다)

| 이름 | 값 | 어디에 쓰나 |
| --- | --- | --- |
| 주 색상 (`primary`) | `#1D4F91` | 버튼, 강조. 버튼 글자는 `background`를 쓴다 |
| 배경 (`background`) | `#F7F8FA` | 화면 바탕 |
| 글자 (`text`) | `#1F2933` | 본문 |
| 간격 단위 (`space`) | `8px` | 여백의 기본 단위. 여백은 이 값의 배수로 쓴다 |
| 오류 색 (`danger`) | `#B42318` | 오류 표시, "자동 점검 실패" |

명암비 계산값(WCAG 공식, 2026-11-02): `primary`와 `background` 7.66:1, `text`와 `background` 13.89:1, `danger`와 `background` 6.19:1. 상태는 색만으로 구분하지 않고 항상 글자를 같이 표시한다.

## 화면 목록

MVP의 기능 9개(F-01~F-09)를 화면 9개에 1:1로 연결했다. 화면 이름 뒤 괄호는 사용하는 역할이다.

| 화면 | 보여 줄 정보 | 입력·버튼 | 연결된 기능 ID (`F-xx`) | 폴더 |
| --- | --- | --- | --- | --- |
| 내 준비 건 (이용자) | 본인 준비 건 목록(생성 일시, 현재 상태), 지원 유형 F-6-1, 항목별 거절 사유, 식별정보 발견 위치(파일명·페이지 또는 상황 설명)와 수정 안내 | 상황 설명, 모의 PDF, 표시 언어 선택, 제출, 상세 열기. 반려·거절 뒤 수정해 다시 제출 | F-01 | 미정 |
| 기준 관리 (담당자) | 공통·관서별 기준, 적용 절차·관서, 공식 원문, 출처·확인일·버전, 등록 거절 사유, "관서 확인 필요" 표시 | 기준 정보 입력, 등록·변경 | F-02 | 미정 |
| 자동 점검 결과 (담당자) | 상황 설명·서류, 주의점·누락 가능성·추가 준비 서류 후보, 항목별 근거 기준 ID·출처·기준일, "자동 점검 실패"·"확인 필요" 표시와 사유 | 검토로 이동 | F-03 | 미정 |
| 검토·승인 (담당자) | 분석 항목, 원문·기준 출처·기준일·버전, 미해결 실패·확인 필요 항목, 승인 불가 사유 | 항목 수정·삭제, 확인 필요 처리 사유 입력, 승인, 사유 입력 후 반려. 미해결 항목이 있으면 승인 비활성 | F-04 | 미정 |
| 승인 결과 (이용자) | 승인된 항목을 한국어·선택 모국어로 나란히 표시, 항목별 근거 출처·기준일 | 준비 항목 체크로 이동 | F-05 | 미정 |
| 준비 항목 체크 (이용자) | 승인된 항목별 준비 여부, 미선택 항목 표시 | 항목별 준비함/아직 선택, 확인 요청 | F-06 | 미정 |

| 준비 건 상태·취소 (이용자) | 현재 상태, "담당자 검토 중" 표시, 반려 사유, 취소 일시·취소 전 상태, 끝 상태 안내 | 다음 화면으로 이동, 취소 확인 후 취소(진행 중 6개 상태만) | F-08 | 미정 |
| 검토 대기 목록 (담당자) | 담당자 부재 중 점검이 끝난 건을 포함한 `담당자 승인 대기`·`준비 확인 요청` 건, 생성 일시, "자동 점검 실패" 표시 | 상세 열기 | F-09 | 미정 |

- F-10 외부 알림은 MVP에서 제외해 화면이 없다. 화면 안 대기·보완 표시는 위 화면에 포함한다.
- US-09 이력 조회는 선택 스토리라 화면에 넣지 않았다. 필수 스토리의 이력 기록은 서버에서 처리한다.
- 실제 민원 접수·허가처럼 보이는 표현은 쓰지 않는다. 버튼과 상태 이름은 도메인 표기를 그대로 쓴다.

### 상태별로 보이는 화면

| 상태 | 이용자 | 담당자 |
| --- | --- | --- |
| 준비중 | 준비 건 상태·취소, 내 준비 건(수정) | 없음 |
| 자동 점검중 | 준비 건 상태·취소 ("담당자 검토 중"만) | 없음 |
| 담당자 승인 대기 | 준비 건 상태·취소 ("담당자 검토 중"만) | 검토 대기 목록 → 자동 점검 결과 → 검토·승인 |
| 서류 준비중 | 승인 결과, 준비 항목 체크, 준비 건 상태·취소 | 없음 |
| 준비 확인 요청 | 승인 결과, 준비 건 상태·취소 | 검토 대기 목록 → 보완·완료 확인 |
| 보완 요청 | 보완·완료 확인, 준비 건 상태·취소 | 없음 |
| 준비 확인 완료 | 승인 결과, 보완·완료 확인 (읽기 전용) | 보완·완료 확인 (읽기 전용) |
| 취소 완료 | 준비 건 상태·취소 (읽기 전용) | 없음 |

## 모든 화면에 있어야 하는 상태
| 상태 | 어떻게 보이나 |
| --- | --- |
| 빈 화면 (데이터 없음) | 없는 이유 한 줄과 할 수 있는 다음 행동 1개를 보여 준다. 비어 있어도 화면 제목은 유지한다 |
| 오류 | `danger` 색과 글자로 무엇이 왜 실패했는지 표시한다. 입력 오류는 해당 항목 옆에, 그 밖의 오류는 화면 위쪽에 표시하고 입력값은 지우지 않는다. 401은 모의 계정 선택 안내, 403은 권한 없음 안내만 보여 주고 준비 건 내용은 표시하지 않는다. 거절된 요청은 화면의 상태 표시를 바꾸지 않는다 |
| 불러오는 중 | "불러오는 중" 글자를 표시한다. 요청이 끝날 때까지 해당 버튼을 비활성화해 중복 클릭을 막고, 응답 전에 상태가 바뀐 것처럼 표시하지 않는다 |
| LLM 결과를 사람이 확인하기 전 | 이용자 화면에는 "담당자 검토 중"만 표시하고 분석 본문·요약·항목 수를 표시하지 않는다. 담당자 화면에는 "담당자 확인 전 초안" 라벨을 붙인다 |

`자동 점검중`은 로딩이 아니라 준비 건의 상태다. 화면을 나갔다 돌아와도 서버가 준 상태를 그대로 표시한다.

### 화면별 빈 화면·오류·로딩

| 화면 | 빈 화면 | 오류 | 불러오는 중 |
| --- | --- | --- | --- |
| 내 준비 건 | "아직 준비 건이 없습니다"와 새 준비 건 만들기 | 항목별 거절 사유, 식별정보 발견 위치 | 목록을 불러오는 중, 제출 버튼 비활성 |
| 기준 관리 | "등록된 기준이 없습니다"와 기준 등록 | 빠진 필수 정보 표시, 기존 기준은 그대로 표시 | 기준을 불러오는 중, 등록 버튼 비활성 |
| 자동 점검 결과 | 분석 항목이 없으면 "자동 점검 실패"와 사유 | 실패 사유 표시, 목록으로 돌아가기 | 점검 결과를 불러오는 중 |
| 검토·승인 | 분석 항목이 없으면 승인 불가 사유와 반려 안내 | 승인 거절 사유(버전 불일치, 미해결 항목, 상태 불일치). 이전 결과는 공개되지 않았음을 표시 | 승인·반려 버튼 비활성 |
| 승인 결과 | 해당 없음. 승인 전에는 이 화면으로 들어오지 않고 "담당자 검토 중"을 표시 | 결과를 불러오지 못했다는 안내 | 승인 결과를 불러오는 중 |
| 준비 항목 체크 | 해당 없음. 승인된 항목이 없으면 이 화면으로 들어오지 않음 | 미선택 항목 표시, 버전 불일치 거절 사유 | 확인 요청 버튼 비활성 |
| 보완·완료 확인 | 보완 항목이 없으면 "보완 항목 없음" | 완료 거절 사유, 항목·이유 누락 표시 | 보완 요청·완료·수정 시작 버튼 비활성 |
| 준비 건 상태·취소 | 해당 없음. 건이 없으면 내 준비 건으로 이동 | 취소 거절 사유 | 상태를 불러오는 중, 취소 버튼 비활성 |
| 검토 대기 목록 | "검토할 준비 건이 없습니다" | 목록을 불러오지 못했다는 안내 | 목록을 불러오는 중 |

오류 응답의 형식은 `API.md`가 미정이라, 위 표는 인수 조건에 있는 거절 사유만 적었다.
