- 작성일: 2026-11-09

## 최종 선택

| 항목 | 선택 | 이유 |
| --- | --- | --- |
| 화면 | React·TypeScript 웹 (Vite) | 팀이 써 본 도구. 휴대폰 브라우저 폭에서도 쓰도록 반응형으로 만든다 |
| 서버 | Python·FastAPI (비동기, SQLAlchemy async) | 팀 전원이 써 본 프레임워크. 법령 처리·LLM 호출을 Python 안에서 이어서 구현한다 |
| DB | PostgreSQL 16+ + pgvector | 조문 임베딩 벡터 검색과 전문 검색을 한 DB에서 한다 |
| LLM | OpenAI (구조화 출력 + 임베딩) | 구조화 출력으로 인용 조문을 받아 코드로 검증하기 쉽다. 모델 ID는 연동 때 정한다 |
| 마이그레이션 | Alembic | 스키마 변경 이력 관리 |
| 테스트 | pytest (서버), `npm run build`·`npm run lint` (화면) | CI에서 Postgres+pgvector 서비스로 실행 |
| 개발용 LLM 대체 | `LLM_FAKE=true` | API 키 없이 화면 흐름을 확인한다. 모든 문구에 개발용 표시를 붙이고, 시연 때는 반드시 끈다 |

## 선택하지 않은 것과 이유

| 후보 | 이유 |
| --- | --- |
| MySQL | 벡터 검색을 따로 붙여야 한다. 조문 검색은 BM25와 벡터를 같이 써야 해서 pgvector가 편하다 |
| 별도 벡터 DB (Pinecone·Chroma 등) | 법령 수천 조문 규모라 Postgres 하나로 충분하고, 운영할 것이 하나 줄어든다 |
| 모바일 앱 | 데모와 팀 개발 속도를 위해 웹 하나로 간다. 반응형으로 휴대폰에서도 쓴다 |

## LLM 연결

- 서버에서만 OpenAI를 부른다. 브라우저에 키를 두지 않는다. 키는 `backend/.env`에만 두고 저장소에 올리지 않는다.
- 보내는 것: 마스킹한 질문, 마스킹한 서류 추출 텍스트, 검색된 조문 원문·요약, 개인화 질문 답변.
- 보내지 않는 것: 식별정보 패턴(마스킹으로 제거), 원본 파일, 익명 사용자 ID.
- 응답은 구조화 출력(JSON 스키마)으로 받고, 인용 조문은 코드로 다시 검증한다.

## 예상 어려움과 대응

| 어려움 | 대응 |
| --- | --- |
| 한국 법령 데이터 확보 | 법제처 국가법령정보 OPEN API와 하이코리아 안내 매뉴얼을 먼저 실제로 받아 본다 `[추정: 사용 가능 여부 확인 전]` |
| 한국어 검색 품질 (조사·띄어쓰기) | BM25에 한국어 2-gram 또는 형태소 토큰화, 조문별 요약 임베딩, 체류 용어집(베트남어↔한국어) |
| 답변 지연 | SSE 스트리밍으로 생성되는 대로 보여 주고, 긴 조문은 관련 항만 넘긴다 |
| 잘못된 인용·오래된 조문 | 인용 검증(존재·현행·원문 일치), 실패 시 1회 재생성, 그래도 실패하면 "원문 확인 필요" |
| 로컬 설치 차이 | Python 3.11 이상, Postgres는 brew 또는 docker compose. README에는 실제로 돌려 본 명령만 적는다 |
