# 우리 팀의 첫 기능

> **저장 위치:** `docs/decisions/first-feature.md`

> **사용 방법**
> 1. 2-2에서 만든 뼈대 위에 **기능 하나**를 끝까지 만듭니다. 어떤 기능인지는 **팀이 고릅니다.** Claude가 정해 주지 않습니다. Claude는 후보의 빈틈을 찾아 줄 수만 있습니다.
> 2. 기능은 `backlog.md`의 **필수 스토리 하나**입니다. 인수 조건에 `미정`이 없고, 화면·서버·데이터를 **모두 거치고**, 오늘 안에 끝낼 수 있게 작은 것을 고릅니다. LLM 호출이 들어간 기능은 오늘은 피합니다(키와 실패 시 동작까지 정해야 해서 범위가 커집니다).
> 3. 이 파일은 **PM이** 팀 결정을 받아 적습니다. 2절 셋째 칸(테스트할 내용)은 **테스트 담당이 구현 전에** 적습니다. 입력과 기대 결과는 인수 조건과 `API.md`에 적힌 것만 씁니다. 같은 파일을 동시에 고치지 않습니다. 후보 비교는 팀 채팅의 후보 표로 하고 여기에는 고른 이유만 적습니다. 승인한 계획의 영역별 할 일도 문서에 옮겨 적지 않고 PM이 팀 채팅에 올립니다.
> 4. 2절의 완성 기준은 **`backlog.md`의 인수 조건에서 가져옵니다.** 새로 만들지 않습니다. 정하지 않은 규칙은 `미정`으로 남깁니다.
> 5. `>`로 시작하는 안내 문장은 지워도 됩니다.

- 작성일: 2026-11-03
- 고른 스토리: `US-01` 상황 설명과 서류로 준비 건 만들기 (기능 ID `F-01`) — PM 결정 (2026-11-03)

- 고른 이유 (우리 팀 상황에서): 첫 데모 흐름 1단계라 다른 스토리가 모두 이 준비 건에서 시작한다. 생성 화면 → FastAPI → MySQL 저장 → 목록 화면까지 한 번에 지나가고 LLM 호출이 없다.
- US-01 미확정을 다루는 방법:
  - PDF 10MB·5개, 상황 설명 1,000자는 팀 설계값이다. 서버 설정값 한 곳에 모아 두고, 클라이언트 확인 뒤 바뀌면 그 값만 고친다.
  - 표시 언어 선택지는 첫 데모 모국어(H2)가 정해지지 않아 오늘은 만들지 않는다. 2절 1·4번의 표시 언어 부분은 "아니오"로 남긴다.
  - 관할 관서 입력은 백로그에서도 미확정이라 오늘 범위에 없다.
- 고르지 않은 후보와 이유 (다음 시간 이후에 다시 볼 것):
  - US-08 취소: 인수 조건에 걸리는 미확정이 없어 가장 가까운 대안이었다. 다만 진행 중 상태의 건이 먼저 있어야 해서, 시드 데이터로 건을 만들거나 US-01이 먼저 있어야 한다.
  - US-06 보완 요청, US-07 준비 확인 완료: `준비 확인 요청` 상태까지 간 건과 승인된 준비 항목이 필요하다. 앞 단계(US-02·03·05)가 없으면 시드 데이터가 많아지고 오늘 안에 끝내기 어렵다.

## 1. 오늘 만드는 범위

| 만드는 것 | 만들지 않는 것 (이유) |
| --- | --- |
| 생성 화면: 지원 유형(F-6-1), 상황 설명, PDF 파일 입력 | 표시 언어 선택 (선택지 미정, H2) |
| 서버: 입력 검사 후 준비 건 1개 저장, 상태 `준비중`, 소유자 = 제출한 이용자 | 자동 점검 시작(US-02), PDF 텍스트 추출 (LLM·점검 범위라 다음 시간) |
| 목록 화면: 새 건이 생성 일시와 함께 1줄 보임 | 권한 401/403 (모의 계정 구분 방식이 DATA-MODEL에서 아직 안 정해짐) |
| 거절 시 해당 항목과 거절 사유 표시 | 관할 관서 입력 (백로그 미확정) |

> 한 스토리 안에서도 오늘은 **끝까지 이어지는 가장 작은 흐름**만 만듭니다. 나머지 인수 조건은 다음 시간으로 남기고, 어느 것을 남겼는지 아래 표에 적습니다.
