## 1. 무엇을 만드나
베트남 출신 결혼이민자와 한국인 배우자가 F-6 체류 관련 질문과 서류를 가져오면 AI가 바로 답하는 웹 서비스.

- 답변 근거: 한국 출입국·체류 법령
- 답변 언어: 베트남어(기본) 또는 한국어
- 근거 표시: 조문 한국어 원문을 함께 보여 준다
- 담당자 승인 단계는 없다. 대신 인용이 원문에 실제로 있는지 코드로 검증한다.
- 면책 문구: 법률 자문이 아니라는 안내와 외국인종합안내센터 ☎1345를 항상 표시한다.

핵심 기능은 두 가지다.
1. **AI 질문**: 질문하면 법령을 검색해 답한다. 답변 속 [n]이 조문 인용이고, 인용과 숫자를 검증한다.
2. **서류 분석**: 서류를 올리면 다음 순서로 진행한다.
   - 서류 종류를 파악하고 개인화 질문을 낸다
   - 답변을 받은 뒤 조항을 꼭 확인(must_check)·주의(caution)·일반(general)으로 분류한다
   - 주의점을 정리하고 다음 행동 체크리스트를 만든다

## 3. 기술 스택
- 백엔드: Python 3.12, FastAPI, SQLAlchemy(async), Alembic
- DB: PostgreSQL 16 + pgvector (Docker, 호스트 포트 5433)
- LLM: OpenAI. 모델은 환경변수로 바꾼다. 기본값은 다음과 같다.
  - 답변: `gpt-5`
  - 질의 재작성·요약: `gpt-5-mini`
  - 임베딩: `text-embedding-3-large`, 1536차원
- 프론트: React + TypeScript (Vite), 웹
- 법령 원문: legalize-kr GitHub 저장소. 마크다운 형식이고, 오늘 시행 중인 판을 고른다.

## 4. 로컬 실행
```bash
cd backend
python3.12 -m venv .venv && .venv/bin/pip install -e '.[dev]'
docker compose up -d db                   # pgvector, localhost:5433
.venv/bin/alembic upgrade head
.venv/bin/python -m ingest load           # data/laws → 조문·청크·관계 그래프 (수 초)
LLM_FAKE=true .venv/bin/uvicorn app.main:app --reload --port 8000
```
- 확인: `curl http://127.0.0.1:8000/health` → documents 11, llm_fake true
- 테스트:
  - DB 없이: `.venv/bin/python -m pytest -q`
  - DB 포함: `TEST_DB=1 .venv/bin/python -m pytest -q` (46개 통과)
- 린트: `.venv/bin/ruff check app ingest tests scripts`
- `LLM_FAKE=true`: OpenAI 없이 고정 응답을 낸다. 답변에 `[DEV FAKE RESPONSE]`가 붙고, 인용은 실제 검색된 조문에서 잘라 쓴다.
- 법령 다시 받기: `python -m ingest fetch`, 이어서 `python -m ingest load`
- 시연 서류 다시 만들기: `python scripts/make_demo_docs.py`

## 6. API 요약 (`/api/v1`)
공통:
- 서류 API는 `X-Client-Id` 헤더가 필수다(8~64자). 브라우저 localStorage에 UUID를 저장해 쓴다.
- 채팅은 헤더가 없어도 되지만, `analysis_id`를 보낼 때는 필요하다.

| 요청 | 설명 |
| --- | --- |
| `POST /chat/stream` | SSE. 이벤트 순서: `stage` → `delta`… → (`reset`) → `answer` / `error` |
| `POST /chat` | 최종 답변만 JSON으로 돌려준다 |
| `GET /provisions?id=` | 조문 원문, 요약, 시행 여부 |
| `GET /provisions/related?id=` | 관련 조문 (REFERENCES/GUIDES, 들어오는 방향/나가는 방향) |
| `GET /search?q=` | 검색 디버그용 |
| `POST /documents` | multipart `file`, `lang`. 201을 주고 상태는 `questions` |
| `GET /documents` | 내 분석 목록 |
| `GET /documents/samples` | 샘플 서류 목록 |
| `POST /documents/samples/{id}` | 샘플로 분석 건 생성 |
| `GET /documents/{id}` | 상태·단계·결과. 화면이 폴링한다 |
| `POST /documents/{id}/answers` | `{answers: [{question_id, option_id?, text?}]}`. 202를 주고 상태는 `analyzing` |
| `POST /documents/{id}/checklist` | `{index, done}`. 상태가 `review` ↔ `done`으로 바뀐다 |
| `POST /documents/{id}/cancel` | 취소 |
| `DELETE /documents/{id}` | 삭제 |
| `GET /health` | documents, provisions, chunks, embedded, llm_fake |

채팅 요청 본문:
```json
{ "message": "...", "lang": "vi", "history": [], "session_id": "...", "analysis_id": null }
```
- `message`: 1,000자 이하
- `lang`: `vi` 또는 `ko`
- `history`: 최대 20개
- 응답 주요 필드: `answer`, `citations[{index, provision_id, quote_ko, quote_translation, verified}]`, `confidence`, `needs_expert`, `follow_up_questions`, `disclaimer`, `sources`, `number_checks`

서류 분석 응답:
- 질문은 `intake.questions[{id, text, why, options[{id,label}], allow_free_text}]`에 있다.
- `result`의 주요 항목: `summary`, `summary_simple`, `clauses[{category: must_check|caution|general, ...}]`, `cautions`, `next_actions`, `open_questions`, `confidence`, `needs_expert`
- `checklist`는 `[{index, done}]` 형식이다.

오류 코드:
| 코드 | 뜻 |
| --- | --- |
| 400 | Client ID 없음 |
| 404 | 없거나 남의 건 |
| 409 | 지금 상태에서 할 수 없음 |
| 413 | 10MB 초과 |
| 415 | PDF·DOCX가 아님 |
| 422 | 입력 오류. 답변 누락이면 `missing_question_ids`가 같이 온다 |
| 502 | LLM 오류 |

## 7. 서류 분석 상태
```
uploaded → questions → analyzing → review ↔ done
analyzing → failed → (답변 다시 제출) analyzing
uploaded·questions·analyzing·review → canceled
```
- `done`과 `canceled`는 끝 상태다. 분석 시작·재시도·취소를 하면 409를 받는다. 삭제는 언제든 된다.
- 취소하면 job_id를 지운다. 그래서 늦게 도착한 분석 결과는 저장되지 않는다.
- 식별정보는 DB 저장 전과 LLM 전송 전에 가린다. 몇 개를 가렸는지는 `masked_count`로 돌려준다.
- 스캔 PDF와 사진은 받지 않는다(OCR 없음).

### ② 프론트엔드 (`frontend/`, 새로 작성)
- 공통 준비
  - `X-Client-Id` 생성·저장
  - API 클라이언트. 서버는 `http://127.0.0.1:8000`이고, CORS는 `localhost:5173`만 허용되어 있다.
  - 베트남어/한국어 전환
  - 면책 문구
- 화면
  1. 홈: AI 질문과 서류 분석으로 들어가는 입구, ☎1345 안내
  2. AI 질문
     - SSE 스트리밍을 받는다. fetch와 ReadableStream으로 파싱한다. POST라서 EventSource는 쓸 수 없다.
     - 진행 단계를 표시한다.
     - `[n]`을 누르면 인용 카드를 연다. 카드에는 원문, 번역, 검증 표시를 넣는다.
     - 후속 질문 버튼을 둔다.
  3. 조문 보기: 원문, 요약, 관련 조문 이동
  4. 서류 분석
     - 업로드 또는 샘플 선택
     - 질문에 답하기
     - 진행 중 화면: 1~2초 폴링, 취소 버튼
     - 결과: 분류별 조항, 주의점, 체크리스트
     - 이 서류에 대해 추가 질문: 채팅 요청에 `analysis_id`를 함께 보낸다
  5. 내 분석 목록과 삭제
- 상태마다 빈 화면, 오류, 로딩 표시를 모두 둔다.
- 디자인은 `docs/DESIGN.md`를 따른다. KoNam 모바일 화면 구성을 참고하되 웹 레이아웃으로 만든다.

### ③ 실제 LLM 연결과 품질 확인
- 키는 각자 `backend/.env`에 `OPENAI_API_KEY=...`로 넣고, `LLM_FAKE`는 끈다. 키는 절대 커밋하지 않는다.
- `python -m ingest summarize --lang vi`로 조문별 베트남어 요약과 임베딩을 만든다.
  - 지금은 임베딩이 0개라 BM25 검색만 동작한다.
  - 가짜 모드에서는 임베딩을 저장하지 않게 막혀 있다.
- 질문 10~20개로 평가셋을 만들고 다음을 기록한다.
  - 인용 검증 통과율
  - 숫자 검증 결과
  - 오답 사례
- 예전 평가셋은 교통법용이라 삭제했으므로 새로 만들어야 한다.
