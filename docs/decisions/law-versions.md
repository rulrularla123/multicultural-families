## 무엇을 바꿨나

| 항목 | 내용 |
| --- | --- |
| 판 식별 | 법령마다 적재한 판의 법령MST(법령일련번호)·법령ID·공포번호·적재 시각을 저장한다 (`alembic 0002`) |
| 최신 판 확인 | `python -m ingest versions`가 적재한 판과 지금 시행 중인 판을 비교해 `current`·`upcoming`·`outdated`·`unknown`을 저장한다 |
| 비교 대상 | `LAW_GO_KR_OC`가 있으면 국가법령정보센터 Open API(법제처 공식) 현행 목록, 없거나 실패하면 legalize-kr 최신 판·커밋 이력 |
| 동기화 | `python -m ingest sync`가 확인 결과 `outdated`인 법령만 받아 재적재하고, 그 법령의 요약·임베딩만 다시 만든 뒤 다시 확인한다. 다른 법령의 청크·임베딩은 그대로 둔다 |
| 공식 링크 | 조문 화면에 "국가법령정보센터에서 이 조문 보기"(현행 판의 해당 조)와 "이 판 원문"(적재한 판) 링크 |
| 화면 경고 | 조문 화면에 공포일·공포번호·시행일·확인 결과. 답변·분석 근거에 `새 판 시행 중`·`최신 판 확인 필요` 표시. 홈 법령 데이터에 확인 상태 |
| 상담 안내 | 인용 법령보다 새 판이 시행 중이면 `needs_expert=true`와 1345 안내. 확인을 못 했거나 7일이 지났으면 공식 원문 대조 안내 |

## 확인한 것

- [사실] 2026-11-17 legalize-kr 기준 `python -m ingest versions` 실행 결과: 11개 법령 모두 적재한 판이 현행. `국적법`은 2026-12-03, `다문화가족지원법`은 2026-12-10 시행 예정 개정이 있다(`upcoming`).
- [사실] `https://www.law.go.kr/LSW/lsInfoP.do?lsiSeq=290729`와 `https://www.law.go.kr/법령/출입국관리법시행령/제12조`가 HTTP 200으로 열리고 제목이 해당 법령이다(curl).
- [사실] 임시 DB에서 출입국관리법을 옛 판처럼 바꿔 두고 `python -m ingest sync`(LLM_FAKE=true)를 실행했다. 출입국관리법만 재적재되어 현행 판(MST 290729)으로 돌아왔고, 국적법의 청크·임베딩·요약은 그대로였다. `data/laws` 파일은 바뀌지 않았다.
- [사실] 요약·임베딩 재생성 경로는 가짜 LLM 함수로 DB 테스트(`test_sync_reloads_only_changed_law_and_reembeds`)만 했다. 실제 OpenAI 호출로는 실행하지 않았다.
- [추정] legalize-kr이 공식 사이트보다 늦으면, 공식 사이트 기준으로 새 판을 찾아도 받을 원문이 없어 `sync` 뒤에도 옛 판(`outdated`)으로 남는다. 이때 명령이 "아직 옛 판"으로 출력한다.
- [추정] 조 단위 링크가 화면에서 해당 조 위치로 바로 이동하는지는 브라우저로 확인하지 않았다. 국가법령정보센터 페이지가 스크립트로 본문을 그리기 때문이다.
- [가정] 국가법령정보센터 Open API 응답 필드(`법령일련번호`, `법령명한글`, `시행일자`, `현행연혁코드`)는 인증값이 없어 실제 응답으로 확인하지 못했다. 단위 테스트는 이 형식을 가정한 가짜 응답으로만 돌렸다. OC를 받은 뒤 실제 응답으로 확인해야 한다.

## 정하지 않은 것

- 실행 주기와 담당자. 지금은 사람이 `sync`를 돌린다. 주기 실행(CI 일정·서버 cron)과, 바뀐 법령을 사람 검토 없이 자동 반영할지는 팀이 정한다.
- 국가법령정보센터 Open API 인증값(OC) 발급 여부와 담당자.
- 백로그 US-07 인수 조건에 "최신 판 확인" 항목을 넣을지 (`backlog.md` 수정은 팀 확인 대상).
