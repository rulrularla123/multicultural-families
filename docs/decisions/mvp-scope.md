## 포함 (8주 안에 반드시 동작 — 필수 스토리 전부, 취소·반려 스토리 포함)
| 스토리 | 기능 (F-__) | 왜 필수인가 |
| --- | --- | --- |
| US-01 상황 설명과 서류로 준비 건 만들기 | F-01 | 첫 데모 흐름 1단계. 클라이언트가 체크박스보다 상황 설명 기반 안내를 요청함(피드백 11) |
| US-02 등록된 기준으로 서류 자동 점검하기 | F-02, F-03, F-09 | 첫 데모 흐름 2~3단계. 필수 조건 2(LLM)가 들어가는 자리이며 담당자 부재 중 검증 요구(피드백 4·9). 기준 등록·변경과 변경 시 재점검은 자동 점검의 전제라 함께 포함(backlog 공통 조건) |
| US-03 담당자가 분석 결과를 승인해 두 언어로 공개하기 | F-04, F-05 | 첫 데모 흐름 4단계. 모든 준비 건에 담당자 승인 필요(피드백 1), 두 언어 동시 표시(피드백 12) |
| US-04 담당자가 분석 결과를 반려하기 | F-04 | 반려 경로. LLM 결과가 틀렸을 때 이용자에게 공개되지 않게 막는 유일한 경로 |
| US-05 준비 상태를 체크하고 확인 요청하기 | F-06 | 첫 데모 흐름 5단계 |
| US-06 담당자가 보완 요청하고 이용자가 다시 준비하기 | F-07 | 되돌림 경로. 부족한 상태로 완료되는 것을 막음 |
| US-07 담당자가 준비 확인 완료하기 | F-07 | 첫 데모 흐름 6단계(끝 상태) |
| US-08 이용자가 진행 중인 준비 건 취소하기 | F-08 | 취소 경로. 모든 진행 상태에서 끝 상태로 가는 전이 |

## 제외 (이번에 만들지 않음)
| 제외 항목 | 왜 뺐는가 | 나중에 넣으면 영향 범위 |
| --- | --- | --- |
| 회원가입·로그인·마이페이지 | 상태 전이·LLM과 관계없고, 권한 구분은 모의 계정 2개(이용자·담당자)로 테스트할 수 있음 | 인증 모듈 추가, 모든 API의 계정 확인 부분 교체 |
| 스캔 PDF OCR | OCR 정확도 검증 부담이 크고 지원 여부가 미정(제안서 Ⅳ-13). MVP는 텍스트 PDF만 받고 추출 실패는 US-02 실패 경로로 처리 | US-02 입력 처리 단계 추가, 식별정보 검사 대상 확대 |
| 실제 서류·실명 정보 수집 | 동의·보관·삭제·마스킹 정책이 미확정(H4). 데모는 모의 서류만 사용 | 개인정보 처리 동의, 저장 암호화, 보관 기간·삭제 기능 |
| 실명·주소 자동 검출 | 패턴으로 검출할 수 없어 별도 모델이 필요함. 모의 서류만 쓰므로 MVP에서는 번호 패턴만 검사 | US-02 식별정보 검사 로직 교체, 오탐·미탐 테스트 추가 |
| F-6-1 외 체류 유형 | 유형마다 기준 목록과 검토자가 필요함. 한 유형으로 전체 흐름을 먼저 검증 | 기준 시드 데이터 추가, US-01 유형 선택지 확대 |
| 서류 진위 판정·개별 사건 법적 판단 | 서비스 범위 규칙 R1. 틀리면 이용자가 잘못 행동하고 책임을 질 수 없음 | 넣지 않음 (전문기관 안내로 대체) |
| 민원 제출·예약·허가 결과 조회 | 외부 기관 시스템 연동이 필요하고, 준비 확인 완료와 허가 완료를 혼동시킬 위험이 있음 | 외부 API 연동, 상태 흐름에 외부 상태 추가 |
| 외부기관으로 정보 자동 전송 | 이용자 동의 범위와 수신 기관 협조가 확인되지 않음 | 동의 화면, 전송 이력, 외부 연동 |
| 대기·보완 알림(F-10) | 제안서에서 선택 기능. 화면 상태 표시만으로 첫 데모 흐름을 보여 줄 수 있음 | 알림 채널 동의, 발송 기능. 상태 전이에는 영향 없음 |
| 담당자 부재 시 대체 승인자 지정 | 대체 승인 절차를 클라이언트가 아직 정하지 않음(피드백 3 "추가 확인"). MVP는 승인 대기 유지 | US-03 권한 규칙에 대체 승인자 추가 |

## 첫 데모(3주차)에서 보여줄 것
(user-flows.md의 흐름과 같아야 함)

모의 이용자가 F-6-1 상황을 설명하고 모의 PDF를 올린다(준비중) → 시스템이 식별정보 검사 후 등록 기준과 대조해 분석 결과를 담당자용으로 저장한다(자동 점검중 → 담당자 승인 대기) → 담당자가 근거를 확인해 승인하고 결과가 한국어·모국어로 공개된다(서류 준비중) → 이용자가 준비 항목을 체크해 확인 요청한다(준비 확인 요청) → 담당자가 기준 버전·미해결 보완을 확인해 완료한다(준비 확인 완료).

## 제안서(v2)와 다른 점
> 이주환 담당. 이미 고객에게 낸 v2는 수업 중에 고치지 않습니다. 다른 곳을 **기록만** 하세요.

| 제안서 절 | 제안서(v2)에 적힌 것 | 이 문서(MVP)에서 달라진 것 |
| --- | --- | --- |
| Ⅰ-3 제안 범위 | 상황 설명·관할 관서 확인·서류 업로드 후 공통/관서별 기준으로 AI 대조하고 담당자가 승인한다. 한국어·모국어를 함께 제공하며 첫 데모는 모의 서류를 사용한다. 실제 서류 운영 조건은 후속 확인 대상으로 둔다. | **유지 / 다른 점 없음:** F-6-1 한 유형·외국어 1개 제안, 모든 준비 건의 담당자 승인, 준비 확인과 실제 허가의 구분. **축소:** 현재 작성안의 데모 입력은 등록 공식 원문·유형·언어와 준비 여부이며 PDF 업로드·내용 대조까지 연결되지 않았다. **미반영:** 상황 설명·관서별 추가 기준·두 언어 동시 표시. 이 세 요구는 고객 요청 제외로 판정하지 않고 추가 연결 대상으로 남긴다. 실제 서류는 운영 조건 확인 전 사용하지 않는다는 제한은 유지한다. |
| Ⅳ-11 주요 기능 목록 | 수정 제안서는 F-01~F-10이다. F-03은 서류·상황 대조, F-05는 두 언어 병렬 표시, F-09는 부재 중 점검, F-10은 알림이다. | **번호 차이:** 안내문 기준 5-2의 F-01~F-08을 유지했다. 기존 F-05(확인 요청)→수정 F-06, 기존 F-06(보완/완료)→수정 F-07, 기존 F-07(이력/취소)→수정 F-08, 기존 F-08(알림)→수정 F-10으로 대응한다. **유지:** 담당자 승인·반려, 보완·완료, 이력·취소를 US-04~US-07의 조건으로 작성했다. **미반영:** 기존 F-01~F-04의 PDF·관서 기준·자동 대조 확대, 수정 F-05의 두 언어 표시와 F-09의 부재 중 자동 점검. **상태 차이:** 현재 `안내 검토 대기`와 수정본의 `자동 점검중 → 담당자 승인 대기`를 동일 상태로 취급하지 않는다. |
| Ⅴ 기대 효과와 성공 지표 | 이용자 서류 선택·준비 시간, 담당자 검토·반복 안내 시간, 누락·AI 오지적/미탐지, 자동 점검 종료와 최종 승인 대기 시간을 구분한다. 기준선은 미측정, 수치 목표는 미정이다. | **유지 / 다른 점 없음:** 기준선 미측정·수치 목표 미정, 재방문·비용 절감을 검증된 효과로 주장하지 않는 원칙. **판정 보류:** 지정 자료 5-1은 항목 누락·이해 정답률·목록 작성 시간 중심이다. 현재 인수 조건은 기능의 정상·거절·권한 판단을 다루므로, 인수 조건에 시간 지표가 없다는 이유만으로 Ⅴ의 성공 지표를 축소·제외했다고 판정하지 않는다. 서류 대조 오지적/미탐지·담당자 총 투입 시간·자동 점검과 최종 승인 대기의 측정 계획은 최종 MVP 범위와 함께 별도로 대조해야 한다. 검증 설계안은 같은 유형·관서·기준 버전의 동등한 모의 사례를 사용하고 이용자 작업 시간, 담당자 검토·반복 안내 시간, 승인 대기 시간을 구분해 기록하는 것이다. 참여자·사례 수와 목표값은 후속 측정 계획에서 정하며 임의 수치를 넣지 않는다. |

외부 알림은 현재 US-08의 선택 기능으로 두어 첫 데모의 필수 범위에서 제외했다. 이는 수정 제안서의 알림 후순위 방향과 **다른 점 없음**이다. 최종 범위 합류 때는 필수 검토안 US-01~US-07이 포함 표에서 빠지지 않았는지, 특히 반려 US-04·취소 US-07이 포함되어 있는지 대조한다.
