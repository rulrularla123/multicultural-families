- 기준: [PRD](../PRD.md), [백로그](../requirements/backlog.md)

## 포함

| 스토리 | 기능 | 왜 필수인가 |
| --- | --- | --- |
| US-01 체류 질문하기 | F-01 | 서비스의 첫 입구. LLM이 법령을 근거로 직접 답하는 핵심 기능 |
| US-02 근거 조문 보기 | F-02 | AI 답변을 원문으로 확인하는 장치. 잘못된 답을 사용자가 걸러 낼 수 있게 한다 |
| US-03 서류 올리고 질문에 답하기 | F-03, F-04 | 서류 분석의 시작. 개인 상황에 따라 같은 서류의 의미가 달라진다 |
| US-04 서류 분석 결과 보기 | F-05 | 기한·누락·위험을 쉽게 알려 주는 핵심 결과 |
| US-05 체크리스트로 다음 행동 끝내기 | F-06 | 분석을 실제 행동으로 이어 주고, 분석 건의 끝 상태를 만든다 |
| US-06 내 분석 건 관리 | F-07 | 개인 서류를 사용자가 직접 지울 수 있어야 한다. 취소 경로 |
| US-07 법령 데이터 적재 | F-08 | 모든 답변의 근거 |
| US-08 화면 언어 전환 | F-09 | 결혼이민자와 한국인 배우자가 함께 쓴다 |

선택: US-09 샘플 서류 체험 (필수 스토리가 끝난 뒤).

## 제외

| 제외 항목 | 이유 |
| --- | --- |
| 실제 서류·실명 처리 | 최신 인수인계의 범위 밖. 데모는 가상 안내문만 사용 |
| 하이코리아 매뉴얼 적재 | 현재 수집기는 legalize-kr의 법령을 대상으로 함. 별도 자료 추가는 이번 범위 밖 |
| 로그인·회원가입 | 데모에 필요 없음. 익명 ID로 분석 건을 구분한다 |
| 스캔·사진 서류(OCR) | 인식 정확도 검증 부담이 크다. 글자가 있는 PDF·DOCX만 받는다 |
| F-6 외 체류자격 전체 | 결혼이민 사용자에 집중한다. 일반 질문에는 답하지만 서류 분석 프롬프트와 샘플은 F-6 기준이다 |
| 체류 허가 가능성 판정·개별 사건 법적 결론 | 틀리면 사용자가 잘못 행동한다. 전문가·출입국 상담 안내로 대신한다 |
| 민원 신청·예약·외부 기관 연동 | 서비스는 정보 제공까지만 한다 |
| 실명·주소 자동 마스킹 | 패턴으로 잡을 수 없다. 번호 패턴만 마스킹하고 모의 서류 사용을 안내한다 |
| 모바일 앱 | 반응형 웹 하나로 간다 |
| 알림(기한 알림 등) | 체크리스트의 기한 표시로 대신한다 |

## 이전 제안서와 달라진 점

- 담당자 승인·반려·보완 흐름을 제거하고, AI가 직접 답변·분석하되 인용·숫자는 코드로 검증한다.
- 모의 이용자·담당자 계정 대신 로그인 없는 `X-Client-Id`로 본인 분석 건을 구분한다.
- MySQL·Gemini 대신 PostgreSQL 16 + pgvector·OpenAI를 쓴다.
- 현재 US-01~US-09는 체류 AI 도우미의 스토리다. 이전 이슈 #59~#66의 같은 번호와 의미가 다르다. 이 문서 수정에서 이슈는 닫거나 변경하지 않는다.

## 첫 데모에서 보여 줄 것

1. 질문하기: 베트남어 질문 → 베트남어 답변 스트리밍 → 근거 조문 카드 → 조문 보기
2. 서류 분석: 모의 출입국 통지서 업로드 → 개인 상황 질문 답변 → 분석중 → 결과(분류·주의점·형광펜·근거) → 체크리스트 완료
3. 예외 한 가지: 스캔 PDF 거절 또는 분석 중 취소
