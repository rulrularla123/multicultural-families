## 포함 (8주 안에 반드시 동작 — 필수 스토리 전부, 취소·반려 스토리 포함)
| 스토리 | 기능 (F-__) | 왜 필수인가 |
| --- | --- | --- |
| US-01 상황 설명과 서류로 준비 건 만들기 | F-01 | 첫 데모 흐름 1단계. 클라이언트가 체크박스보다 상황 설명 기반 안내를 요청함(피드백 11) |
| US-02 등록된 기준으로 서류 자동 점검하기 | F-02, F-03, F-09 | 첫 데모 흐름 2~3단계. 필수 조건 2(LLM)가 들어가는 자리이며 담당자 부재 중 검증 요구(피드백 4·9). 기준 등록·변경과 변경 시 재점검은 자동 점검의 전제라 함께 포함(backlog 공통 조건) |
| US-03 담당자가 분석 결과를 승인해 두 언어로 공개하기 | F-04, F-05 | 첫 데모 흐름 4단계. 모든 준비 건에 담당자 승인 필요(피드백 1), 두 언어 동시 표시(피드백 12) |
| US-04 담당자가 분석 결과를 반려하기 | F-04 | 반려 경로. LLM 결과가 틀렸을 때 이용자에게 공개되지 않게 막는 유일한 경로 |
| US-05 준비 상태를 체크하고 확인 요청하기 | F-06 | 첫 데모 흐름 5단계 |
| US-06 담당자가 보완 요청하고 이용자가 다시 준비하기 | F-07 | 되돌림 경로. 부족한 상태로 완료되는 것을 막음 |
| US-07 담당자가 준비 확인 완료하기 | F-07 | 첫 데모 흐름 6단계(끝 상태) |
| US-08 이용자가 진행 중인 준비 건 취소하기 | F-08 | 취소 경로. 모든 진행 상태에서 끝 상태로 가는 전이 |

## 제외 (이번에 만들지 않음)
| 제외 항목 | 왜 뺐는가 | 나중에 넣으면 영향 범위 |
| --- | --- | --- |
| 회원가입·로그인·마이페이지 | 상태 전이·LLM과 관계없고, 권한 구분은 모의 계정 2개(이용자·담당자)로 테스트할 수 있음 | 인증 모듈 추가, 모든 API의 계정 확인 부분 교체 |
| 스캔 PDF OCR | OCR 정확도 검증 부담이 크고 지원 여부가 미정(제안서 Ⅳ-13). MVP는 텍스트 PDF만 받고 추출 실패는 US-02 실패 경로로 처리 | US-02 입력 처리 단계 추가, 식별정보 검사 대상 확대 |
| 실제 서류·실명 정보 수집 | 동의·보관·삭제·마스킹 정책이 미확정(H4). 데모는 모의 서류만 사용 | 개인정보 처리 동의, 저장 암호화, 보관 기간·삭제 기능 |
| 실명·주소 자동 검출 | 패턴으로 검출할 수 없어 별도 모델이 필요함. 모의 서류만 쓰므로 MVP에서는 번호 패턴만 검사 | US-02 식별정보 검사 로직 교체, 오탐·미탐 테스트 추가 |
| F-6-1 외 체류 유형 | 유형마다 기준 목록과 검토자가 필요함. 한 유형으로 전체 흐름을 먼저 검증 | 기준 시드 데이터 추가, US-01 유형 선택지 확대 |
| 서류 진위 판정·개별 사건 법적 판단 | 서비스 범위 규칙 R1. 틀리면 이용자가 잘못 행동하고 책임을 질 수 없음 | 넣지 않음 (전문기관 안내로 대체) |
| 민원 제출·예약·허가 결과 조회 | 외부 기관 시스템 연동이 필요하고, 준비 확인 완료와 허가 완료를 혼동시킬 위험이 있음 | 외부 API 연동, 상태 흐름에 외부 상태 추가 |
| 외부기관으로 정보 자동 전송 | 이용자 동의 범위와 수신 기관 협조가 확인되지 않음 | 동의 화면, 전송 이력, 외부 연동 |
| 대기·보완 알림(F-10) | 제안서에서 선택 기능. 화면 상태 표시만으로 첫 데모 흐름을 보여 줄 수 있음 | 알림 채널 동의, 발송 기능. 상태 전이에는 영향 없음 |
| 담당자 부재 시 대체 승인자 지정 | 대체 승인 절차를 클라이언트가 아직 정하지 않음(피드백 3 "추가 확인"). MVP는 승인 대기 유지 | US-03 권한 규칙에 대체 승인자 추가 |

## 첫 데모(3주차)에서 보여줄 것
(user-flows.md의 흐름과 같아야 함)

모의 이용자가 F-6-1 상황을 설명하고 모의 PDF를 올린다(준비중) → 시스템이 식별정보 검사 후 등록 기준과 대조해 분석 결과를 담당자용으로 저장한다(자동 점검중 → 담당자 승인 대기) → 담당자가 근거를 확인해 승인하고 결과가 한국어·모국어로 공개된다(서류 준비중) → 이용자가 준비 항목을 체크해 확인 요청한다(준비 확인 요청) → 담당자가 기준 버전 일치, 미해결 보완·확인 필요 항목 없음, 모든 항목 "준비함"을 확인해 완료한다(준비 확인 완료).

## 고객이 요청했으나 제외한 것
> 김태후 담당. `client-meeting-1.md`에서 '반영 안 함'으로 판정한 것 중 MVP와 관련된 것을 옮깁니다.

| 요청 | 제외 이유 | 다시 논의할 시점 |
| --- | --- | --- |
| 관서별 추가 서류를 기준에 반영 (피드백 13 '반영', 14 '추가 확인') | 관서별 기준의 출처·갱신 책임자가 미확정이다. MVP는 공통 기준 1개 버전만 시드 데이터로 넣는다(위 제외 표 2행). 제안서 단계에서 '반영'한 요청을 MVP에서 미룬 것이므로 고객에게 따로 알려야 한다. | 다음 미팅에서 관서별 차이 사례·자료 출처·갱신 주체를 확인한 뒤 |
| 담당자 부재 시 승인 방법 (피드백 3 '추가 확인') | 클라이언트가 대체 승인 절차를 아직 정하지 않았다. MVP는 승인 대기를 유지하고, 부재 중에는 자동 점검(US-02)만 한다(위 제외 표 마지막 행). | 다음 미팅에서 대체 승인자·대기 기한을 확인한 뒤 |

- `client-meeting-1.md` '받은 피드백과 처리' 14건 중 '반영 안 함' 판정은 0건이다(반영 11건: 1·4~13, 추가 확인 3건: 2·3·14). 위 표는 '반영'·'추가 확인'으로 받았지만 이번 MVP 제외 표에서 빠진 고객 요청이다.
- 피드백 2(준비 건 생성 시 템플릿 제공, '추가 확인')는 포함 표와 제외 표 어디에도 없다. 넣을지 뺄지 권길현 담당 표에서 정해야 한다.

## 제안서(v2)와 다른 점
> 이주환 담당. 이미 고객에게 낸 v2는 수업 중에 고치지 않습니다. 다른 곳을 **기록만** 하세요.

| 제안서 절 | 제안서(v2)에 적힌 것 | 이 문서(MVP)에서 달라진 것 |
| --- | --- | --- |
| Ⅰ-3 제안 범위 | 상황 설명·관할 관서 확인·서류 업로드 → 공통·관서별 기준으로 AI 대조 → 담당자 승인. 한국어·모국어 1개 동시 표시. 첫 데모는 가상 상황과 모의 서류 이미지로 업로드부터 승인까지 | 같음: F-6-1 한 유형, 모든 건 담당자 승인, 두 언어 동시 표시(US-03), 실제 서류 미사용, 제외 범위(민원 제출·진위 판정 등). 다름: ① 관할 관서 입력은 US-01 미확정으로 남김 ② 업로드는 텍스트 PDF만 받고 스캔·이미지 OCR은 제외 ③ 데모 기준은 공통 기준 1개 버전(관서별 기준 등록 기능은 US-02에 있음) ④ 첫 데모는 승인에서 끝나지 않고 준비 확인 완료까지 보여 줌 |
| Ⅳ-11 주요 기능 목록 | F-01~F-08 필수, F-09 필수 후보, F-10 선택 | 기능 번호는 v2를 그대로 씀(backlog 대응표). F-01~F-08은 US-01~US-08에 모두 포함. F-09는 필수 후보에서 필수로 올려 US-02에 포함. F-10 외부 알림은 제외(제외 표), 화면 안 상태 표시만 유지. F-04의 "승인 대기에서 보완 요청"은 반려(US-04)로 처리하고, 보완 요청은 확인 요청 뒤 단계(US-06)에서만 함 |
| Ⅳ-12 상태 흐름 | 정상 경로 6개 상태, 반려·보완·취소, 기준 버전 변경 시 재점검 | 상태 이름과 정상 경로는 같음. 재점검 조건을 기준 버전 변경뿐 아니라 상황·서류 변경까지 넓힘(backlog 공통 조건). 취소·변경 뒤 늦게 온 점검 결과는 반영하지 않는 조건을 추가함(US-02·08) |
| Ⅳ-13 LLM에 보내지 않을 정보 | 실명·연락처·외국인등록번호·여권번호·주소 등 식별정보 전송 금지 | 자동 검사는 외국인등록번호·여권번호·휴대전화번호 패턴만 함. 실명·주소는 자동 검출하지 않고 비식별 모의 자료만 써서 막음(제외 표) |
| Ⅴ 기대 효과와 성공 지표 | 이용자 준비 시간, 담당자 검토·반복 안내 시간, 누락·AI 오지적/미탐지, 자동 점검 종료와 승인 대기 시간을 나눠 측정. 기준선 미측정, 목표 수치 미정 | 지표 자체는 바꾸지 않음. MVP 스토리에는 측정 기능이 없고, 첫 데모는 기능 시연이라 효과를 측정했다고 쓰지 않음. 측정 방법·사례 수·목표값은 따로 정함 |

외부 알림(F-10)은 제안서에서도 선택 기능이라 제외했다. 필수 스토리 US-01~US-08은 모두 포함 표에 있고, 반려·보완·취소 경로(US-04·US-06·US-08)도 들어 있다.
