## 4-2. 필수 조건 확인

> 점수를 매기기 전에 먼저 거릅니다. **두 칸 중 하나라도 비면 그 후보는 점수표에 올리지 않습니다.** 셋 다 걸러지면 후보를 바꾸거나 범위를 넓혀 다시 찾습니다.

| 후보 | 상태 전이: 핵심 대상과 상태 흐름 (4개 이상, 취소·반려 경로 포함) | LLM: 서비스 안에서 하는 일과 사람이 확인하는 곳 | 통과 |
| --- | --- | --- | --- |
| A | `[가정]` **안내 요청 건**: 질문 접수 → 추가 정보 확인 → 초안 검토 대기 → 안내 제공 → 이용자 확인 완료. 이용자가 질문·추가 정보를 제출하고, 시스템이 허용 분야·입력 조건을 확인한 후 검토 대기로 전환한다. 상담원이 근거와 설명을 확인해 제공하고 이용자가 확인을 마친다. 상담원 반려 → 추가 정보 확인, 이용자 취소 → 취소 완료. 범위 밖 질문 → 전문기관 안내. | `[가정]` 식별정보를 제외한 질문과 공식 자료를 받아 분야 분류·쉬운 다국어 설명 초안을 작성한다. 이용자가 분류를 정정하고, **상담원이 원문과 의미를 비교해 수정·승인한 뒤 제공**한다. 조문 존재 검사만으로 내용의 정확성을 보장하지 않는다. | ☑ 설계 조건 충족. 실제 검토자 확보는 미확인. |
| B | `[가정]` **절차 준비 건**: 준비중 → 안내 검토 대기 → 서류 준비중 → 준비 확인 요청 → 준비 확인 완료. 이용자가 시작·준비 체크·확인을 요청하고, 담당자가 안내 승인과 준비 완료 확인을 한다. 항목 부족 → 보완 요청 → 서류 준비중. 이용자 취소 → 취소 완료. 전이 조건은 아래 표에 명시. | `[가정]` 담당자가 등록한 공식 안내와 선택된 절차 유형을 받아 **쉬운 다국어 설명·준비 항목 초안**을 만든다. 담당자가 원문·항목을 검토한 뒤 제공한다. 필수 서류는 검토된 기준 목록으로 확정하며 LLM이 추가·삭제하거나 완료 상태를 결정하지 않는다. | ☑ 설계 조건 충족. 첫 절차·지원 언어·검토자 검증 필요. |
| C | `[가정]` **상담 연결 준비 건**: 작성중 → 요약 검토 대기 → 연결 안내 준비 → 이용자 전달 완료 → 이용자 종료 확인. 이용자가 질문·연락 동의 범위를 입력하고, 시스템이 필수 항목 확인 후 검토 대기로 전환한다. 담당자가 요약을 승인하고 연락처·전달할 내용을 제공하며 이용자가 종료를 확인한다. 요약 반려 → 작성중, 이용자 철회 → 취소 완료. 외부기관 상담 완료는 우리 상태로 표시하지 않는다. | `[가정]` 이용자가 선택한 비식별 상담 내용으로 한국어 쟁점·질문 요약 초안을 만든다. 이용자가 누락을 확인하고, 담당자가 원문과 비교해 승인한다. 외부기관 전송은 연동·동의 확인 전에는 하지 않고, MVP에서는 이용자에게 보여 주는 상담 준비 요약으로 제한한다. | ☑ 설계 조건 충족. 외부기관 연계와 반복 설명 감소 효과는 미확인. |

통과는 상태와 LLM 역할을 정의했다는 뜻이며 구현·운영 검증을 마쳤다는 뜻은 아니다. 아래의 상태·권한·보완 규칙은 모두 `[가정]`인 서비스 설계안이다. 담당자는 우리 서비스의 지원 담당자이며, 출입국기관의 심사·허가 담당자와 다르다.

### 첫 데모 범위와 확인할 기준

`[가정]` 3주차에는 **한 절차·한국어와 외국어 1개·담당자 검토 화면**으로 다음 한 흐름을 시연한다. 지원 외국어는 검토 가능한 사람이 있는 언어로 팀이 정한다. 모의 데이터로 시연하며 실제 기관이 참여했다고 기록하지 않는다.

> 이용자가 준비 건 생성 → LLM 설명 초안 → 담당자 원문 대조·승인 → 이용자 항목 체크 → 확인 요청 → 누락 항목 보완 요청 → 이용자 수정·재요청 → 담당자 준비 확인 완료
