# 도메인 조사 규칙

> 조사를 시작하기 전에 팀원 모두 이 파일을 읽습니다. 이 파일은 고치지 않습니다.

## 조사 관점

다섯 관점을 모두 함께 조사합니다. 블록마다 다섯 관점이 빠짐없이 채워지는지 함께 확인합니다.

| 관점 | 무엇을 조사하나 |
| --- | --- |
| ① 사람·이용 흐름 | 누가 쓰고, 지금 일(또는 이용·훈련·절차)을 어떤 순서로 하는가 |
| ② 규칙·예외 | 반드시 지켜야 할 규칙(업무 규칙, 서비스·훈련 규칙, 법령·제도), 예외, 경계 사례 |
| ③ 데이터·외부 연동 | 어떤 정보가 오가고, 외부 시스템·서비스와 어디서 닿는가. 개인정보가 있는가 |
| ④ 기존 서비스·벤치마크 | 이미 있는 도구·앱·서비스는 무엇이고 무엇이 불편한가 |
| ⑤ 문제와 손해 | 지금 방식 때문에 누가 시간·돈·신뢰·건강·기회를 얼마나 잃는가 (숫자로 된 근거) |

## 태그 규칙

모든 조사 내용에는 태그를 붙입니다.

| 태그 | 뜻 | 함께 적을 것 |
| --- | --- | --- |
| `[사실]` | 출처로 확인한 내용 | 링크나 자료명 |
| `[추정]` | 여러 자료로 미루어 판단한 내용 | 근거 한 줄 |
| `[가정]` | 확인하지 못했지만 일단 그렇다고 둔 내용 | 5단계에서 클라이언트 질문으로 바꿉니다 |

AI(Claude 등)가 알려준 내용은 출처를 직접 열어 확인하기 전까지 `[추정]`입니다.

## 파일 규칙

| 무엇 | 어디에 | 파일 이름 |
| --- | --- | --- |
| 단계별 표 | `docs/domain/`, `docs/decisions/`, `docs/interview/` | 이미 만들어져 있음. 블록마다 정리 담당 1명이 고칩니다 |
| 논문·자료 근거 카드 | `docs/domain/cards/` | `[관점 번호]-[GitHub 아이디]-[순번].md` (예: `5-ujin-01.md`). 이 이름이 **카드 번호**입니다 |
| AI 확인 기록 | `docs/domain/ai-check-log.md` | 하나의 파일. 맨 아래에 이어서 씁니다 |
| 개인 회고 | `logs/` | `pre-[GitHub 아이디].md` |
| 제안서 | `docs/proposal/` | Word 양식으로 작성. 완성본은 `[팀명]-project-proposal.docx`와 같은 이름의 PDF로 올립니다 |

카드는 `docs/domain/cards/_template.md`를 복사해서 만듭니다. 단계 파일의 표에서 근거를 적을 때는 카드 번호를 씁니다(예: `근거: 5-ujin-01`).
