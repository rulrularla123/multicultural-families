# 5. MVP 가설, 기능 목록, 가정·위험, 클라이언트 질문지, 미팅 준비

> 기록 구분: 아래 내용은 클라이언트 미팅 전 사전활동의 후보 비교·가설 기록이다. 당시 상태 이름·기능 ID·모델 제안은 현재 구현 기준이 아니다. 현재 범위·상태·실패 처리는 [백로그](../requirements/backlog.md)·[사용자 흐름](../requirements/user-flows.md)·[MVP 범위](../decisions/mvp-scope.md), 스택·모델은 [STACK.md](../STACK.md)를 따른다. 초기 가설과 비교 점수는 기록으로 보존한다.

> 목표: 우리가 만들 것과 모르는 것을 목록으로 만들고, 모르는 것을 클라이언트가 답할 수 있는 질문으로 바꾼다.

[4단계](../decisions/topic-selection.md)의 선정 주제 B(체류기간 연장 준비 지원)를 기준으로 작성했다. 문서 기준 주제는 4-5에서 확정했으며 현장 검증은 미팅에서 수행한다. 팀 공동회의를 이미 했다는 뜻은 아니다. 아래 기능·권한·효과·미팅 역할은 모두 `[가정]`인 제안이며, 실제 운영 기관의 승인이나 참여를 확보한 상태가 아니다.

## 5-1. MVP 가설

> 클라이언트 미팅 전 우리의 추측입니다. 미팅 뒤 바뀔 수 있습니다. 제안서 Ⅰ-3 제안 범위, Ⅳ-10 목표 흐름의 바탕이 됩니다.

| 구분 | 내용 |
| --- | --- |
| 핵심 사용자 흐름 1개 (첫 데모에서 보여 줄 것) | 이용자가 지원 유형을 선택해 절차 준비 건을 만든다(**준비중**) → 등록된 공식 원문으로 LLM이 쉬운 설명·준비 항목 초안을 만든다(**안내 검토 대기**) → 담당자가 원문·항목을 대조해 승인한다(**서류 준비중**) → 이용자가 준비 여부를 체크하고 확인을 요청한다(**준비 확인 요청**) → 담당자가 부족 항목과 이유를 남긴다(**보완 요청**) → 이용자가 수정한다(**서류 준비중**) → 다시 요청한다(**준비 확인 요청**) → 최신 기준 버전과 일치하고 미해결 보완이 없을 때 담당자가 완료한다(**준비 확인 완료**). 보완 경로를 한 번 포함해 4-2의 시작부터 끝까지 시연한다. |
| 이 흐름에서 LLM이 쓰이는 곳 | Claude를 활용해 담당자가 등록한 공식 안내와 선택된 절차 유형을 쉬운 다국어 설명·준비 항목 초안으로 바꾼다. 모델이 원문을 임의로 추가하거나 필수 항목·완료 여부를 결정하지 않는다. 담당자가 모든 초안을 승인한 뒤 이용자에게 제공한다. 생성 실패는 준비중에 유지하고 오류 초안은 반려한다. |
| 첫 데모 대상·언어·자료 | 혼인 유지 중인 F-6-1 체류기간 연장 준비 한 유형을 제안한다. 한국어와 담당자가 검토할 수 있는 외국어 1개로 시작하며 언어는 H2 확인 후 정한다. 실제 서류 대신 가상 사례·준비 여부 체크를 사용한다. 기준 목록은 공식 자료를 담당자가 확인해 등록한 버전으로 한정한다. |
| 당장 제외할 것과 이유 | 민원 제출·예약·허가 조회, 모든 체류 유형, 개별 사건의 법적 판단, OCR·서류 진위 판정, 실제 서류 보관, 개인정보의 외부기관 자동 전송은 범위·검증 부담 때문에 제외한다. 준비 확인 완료는 실제 민원 접수·허가 완료를 뜻하지 않는다. |
| 검증할 효과 | 공식 안내만 보는 경우와 검토된 쉬운 설명·목록을 함께 보는 경우의 필수 항목 누락 수·준비 순서 이해 정답률·목록 작성 시간을 비교하고, 담당자 검토 시간도 기록한다. 난이도가 같은 가상 사례로 비교하며 수치 목표는 기준선 확인 후 정한다. 재방문·비용 절감은 측정 전 효과로 주장하지 않는다. |

공통 기준: 공식 안내의 버전이 바뀌면 이전 승인으로 완료하지 않는다. 식별정보·실제 서류 입력은 허용하지 않으며, 입력 검사에서 발견되면 수정 전 Claude 전송을 차단한다. 실제 운영의 보관 기간·삭제·담당자 배정 정책은 질문 7·10에서 확인한다.

## 5-4. 위험 요소

> 제안서 Ⅶ-17의 바탕이 됩니다. 위험은 발생 가능성과 대응을 적은 설계 가정이며 실제 사고 기록이 아닙니다.

| 위험 | 일어나면 생기는 일 | 대응 |
| --- | --- | --- |
| LLM 오역·항목 누락 또는 오래된 안내 | 이용자가 틀린 준비 항목을 따르거나 준비 완료를 허가 완료로 오해한다. | 공식 원문·버전으로 생성 범위를 제한하고 모든 초안을 담당자가 승인한다. 미승인 초안은 숨긴다. 변경 시 재검토하며 승인된 기준 목록·상태 권한을 LLM과 분리한다. 완료 화면에 준비 확인의 범위를 명시한다. |

## 5-5. 클라이언트 질문지

> 총 10개. 우선순위 1~5는 반드시 묻고, **1~3은 제안서 Ⅶ-18에 넣어 미리 보냅니다.** 6~10은 남은 시간 또는 후속 확인으로 진행합니다. 작성 과정에서 질문의 개방성·중립성·결정 연결을 검토하고 문서 검토 기록에 반영했습니다.

각 질문은 최근 사례 → 실제 행동·기준 → 변경할 설계 순으로 듣습니다. 사례가 없다면 없다고 기록하고, 개인정보·실명·서류 사본은 요청하지 않습니다. 아래 문항은 예/아니오형과 해결책 유도 표현을 제거한 문서 검토본입니다.

| 우선순위 | 카테고리 | 질문 | 관련 가정 | 이 답으로 결정할 것 |
| --- | --- | --- | --- | --- |
| 1 | 목적·성공 기준 | 최근 체류기간 연장을 준비한 사례 한 건에서, 이용자가 처음 한 일부터 준비를 마칠 때까지 어떤 일이 있었나요? 가장 시간이 들거나 다시 해야 했던 단계와 그 영향을 설명해 주세요. | H1·H5 | 실제 문제 지점, 후보 B 유지 여부, 비교할 기준선 |
