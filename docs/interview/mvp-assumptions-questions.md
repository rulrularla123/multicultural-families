## 5-5. 클라이언트 질문지

> 카테고리마다 1개 이상, 총 8~10개. 미팅 질문 시간은 팀당 약 12분이므로 우선순위 1~5번은 반드시 묻는 질문입니다. **1~3번은 제안서 Ⅶ-18에 넣어 미리 보냅니다.** 질문을 고칠 때 팀원끼리 서로 읽어 보고 예/아니오로 끝나거나 답을 유도하는 질문을 고칩니다.
>
> 좋은 질문의 조건: ① 예/아니오로 끝나지 않는다 ② 구체적인 사례를 들어 묻는다 ③ 우리 해결책을 정답으로 유도하지 않는다 ④ 답을 들으면 무엇을 결정할지 알고 있다.

| 우선순위 | 카테고리 | 질문 | 관련 가정 | 이 답으로 결정할 것 |
| --- | --- | --- | --- | --- |
| 1 | 목적·성공 기준 | | | |
| 2 | 사용자·권한 | | | |
| 3 | 규칙 | | | |
| 4 | 상태 전이·예외 | | | |
| 5 | 우선순위·범위 | | | |
| 6 | LLM 결과의 확인과 책임 | | | |
| 7 | 데이터·외부 연동·개인정보 | | | |
| 8 | 완료 기준 (어떻게 확인하면 되나) | | | |
| 9 | | | | |

## 5-6. 미팅 역할 분담

> 실제 클라이언트 미팅에서 다섯 명이 하나씩 맡습니다. [팀 역할](../team/roles.md)과 따로 정해도 됩니다.

| 역할 | 하는 일 | 담당 |
| --- | --- | --- |
| 진행자 | 질문 순서·시간 관리, 꼬리 질문 | |
| 기록자 | 답변을 말 그대로 기록 | |
| 꼬리 질문자 | "예를 들면요?", "그 경우 누가요?"로 파고들기 | |
| 시간·가정 체커 | 가정 H1~H5 중 확인된 것을 지우기 | |
| 요약·확인자 | 끝나기 1분 전, 들은 답을 3문장으로 되읽어 클라이언트에게 맞는지 확인 | |

## 5-7. 미팅 전에 다시 볼 것

> 제안서를 보낸 뒤 미팅까지 팀이 함께 확인합니다.

| 확인할 것 | 메모 |
| --- | --- |
| 클라이언트가 제안서 Ⅶ-18의 고객사 설정을 어떻게 정해 올지 예상해 보고, 답에 따라 바뀌는 질문 | |
| 제안서 Ⅶ-16의 `[가정]` 중 틀리면 MVP가 크게 바뀌는 것 | |
| 클라이언트가 상태 흐름이나 LLM 역할을 바꾸자고 하면 우리가 지킬 것과 양보할 것 | |
| 제안서에 쓰지 않았지만 질문받으면 답해야 할 것 (근거 카드 번호) | |
