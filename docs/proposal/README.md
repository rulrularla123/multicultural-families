## 1단계 — Claude Code로 초안 만들기

팀 저장소를 내려받은 폴더에서 Claude Code를 열고 아래 프롬프트를 그대로 붙여 넣습니다.

```text
목표: 우리 팀의 조사 파일을 바탕으로 클라이언트에게 보낼 프로젝트 제안서 초안을 만든다.

현재 상태: docs/domain/, docs/decisions/, docs/interview/, docs/team/ 에 조사 내용이 있다. 제안서의 장 순서와 장마다 바탕이 되는 파일은 docs/proposal/README.md 의 "제안서 구성과 바탕 파일" 표에 있다.

기대 결과: docs/proposal/draft.md 에 그 표의 순서(제안 요약, Ⅰ~Ⅶ, 부록 A·B)와 소제목 그대로 초안을 쓴다.

탐색 범위: docs/ 아래 파일만 읽는다. 웹 검색은 하지 않는다.

제약 조건:
- 조사 파일에서 `>`로 시작하는 안내 문장(그 안의 예시 포함)은 쓰지 않는다. 표에 채워진 행과 `>` 밖의 문장은 모두 팀이 조사한 내용이므로, 안내 예시와 비슷해 보여도 그대로 쓴다.
- 조사 파일에 없는 사실, 숫자, 자료를 새로 만들지 않는다. 채울 내용이 없으면 "[조사 파일에 없음]"이라고 쓴다.
- 03의 3-2 mermaid 그림은 3-2 표와 내용이 같으면 팀이 고친 것으로 보고 Ⅳ-12에 쓴다.
- 조사 파일의 [사실]/[추정]/[가정] 태그와 카드 번호를 그대로 옮긴다.
- 기술 스택, 화면 설계, LLM 모델 이름은 쓰지 않는다.
- 다른 파일은 고치지 않는다.

진행 절차: 표의 장마다 바탕 파일을 읽고 → 한 장씩 초안을 쓰고 → 제안 요약은 마지막에 쓴다. 문장 끝에 바탕이 된 파일과 표 번호를 (출처: 02 2-2)처럼 붙인다. Ⅵ-14 일정은 쓰지 않는다.

검증: 쓴 뒤 Ⅳ-12 상태 흐름에 상태가 4개 이상이고 취소·반려 경로가 있는지, Ⅳ-13에 사람이 확인하는 곳이 있는지 스스로 확인한다.

보고: 장마다 어떤 파일을 바탕으로 했는지 목록과, "[조사 파일에 없음]"으로 남긴 곳을 알려 준다.
```

## 2단계 — 팀이 초안 확인하기

초안을 장별로 나눠 읽고 아래 세 가지를 확인합니다. 찾은 것은 [ai-check-log.md](../domain/ai-check-log.md#제안서-검토-6단계)에 적습니다.

| 확인할 것 | 어떻게 |
| --- | --- |
| ① 조사 파일에 없는 내용이 들어갔는가 | 문장마다 바탕이 된 파일과 표를 찾아 봅니다. 찾을 수 없으면 지우거나 `[가정]`으로 바꿉니다 |
| ② `[사실]` 문장의 출처를 우리가 직접 열어 확인했는가 | 카드 번호를 따라가 카드의 "직접 확인" 칸을 봅니다. 확인하지 않았으면 `[추정]`으로 바꿉니다 |
| ③ 필수 조건 두 장이 기준을 지키는가 | Ⅳ-12: 상태 4개 이상, 취소·반려 경로 1개 이상, 전이마다 누가·조건 / Ⅳ-13: LLM은 초안·요약·분류만, 최종 결정은 규칙이나 사람, 보내지 않을 정보 |

`[조사 파일에 없음]`으로 남은 곳은 조사 파일을 먼저 채우거나, 제안서에서 `[가정]`으로 쓰고 Ⅶ-18 질문으로 넘깁니다.

## 3단계 — 양식에 옮기고 다듬기

1. 양식을 복사해 `[팀명]-project-proposal.docx`로 저장합니다.
2. 확인한 초안을 장별로 옮기고, 회색 안내·예시 글씨를 모두 지웁니다.
3. Ⅵ-14 일정은 '우리 팀 목표' 칸만 우리 주제에 맞게 고칩니다.
4. 제안 요약은 본문을 다 옮긴 뒤 마지막에 씁니다.
5. 본문이 4~5쪽을 넘으면 표의 설명을 줄입니다. 용어와 참고 자료는 부록에 둡니다.

## 4단계 — 올리기

완성본을 docx와 PDF로 저장해 이 폴더에 PR로 올리고, **팀원 5명 모두 Approve**한 뒤 병합합니다. `draft.md`도 함께 올립니다.
