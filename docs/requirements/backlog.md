## 첫 데모 흐름과 공통 조건

핵심 대상은 **절차 준비 건**이다. 정상 경로는 수정 제안서 Ⅳ-12에 맞춰 다음 여섯 상태로 구성한다.

**준비중 → 자동 점검중 → 담당자 승인 대기 → 서류 준비중 → 준비 확인 요청 → 준비 확인 완료**

이용자가 상황 설명과 모의 PDF를 입력하면 등록된 공통·관서별 공식 기준으로 자동 대조한다. 담당자는 결과·근거를 확인해 승인하고, 이용자는 한국어·선택 모국어로 안내를 함께 본 뒤 준비 확인을 요청한다. 취소·반려·보완·재점검 경로는 이 정상 경로에서 분리하되 필수 스토리에 포함한다. `준비 확인 완료`는 실제 민원 접수·허가 완료가 아니다.

- 첫 대상은 F-6-1 한 유형, 한국어와 검토 가능한 외국어 1개로 시작하는 안이다. 외국어·실제 검토자·대상 관서는 미확정이다. 데모는 가상 상황·모의 PDF와 역할별 모의 계정으로 진행한다.
- 업로드와 문서 대조는 필수다. 실제 서류의 동의·접근·마스킹·LLM 전송·보관·삭제 정책 확정 전에는 실제 서류를 처리하지 않는다. OCR 지원은 확정하지 않으며 텍스트를 처리할 수 없는 PDF는 확인 필요로 안내한다.
- 자동 점검은 시스템이 진행 상태를 기록하는 처리다. LLM 결과만으로 담당자 승인 여부·보완 해소·준비 완료를 변경하지 않는다. 승인 전 분석 본문은 담당자용으로 유지한다.
- 점검 결과는 해당 상황·서류·적용 기준 버전에 연결한다. 어느 하나가 변경되어 재점검하면 이전 결과·승인·확인 요청을 완료 근거로 사용하지 않는다. 취소된 건이나 현재 버전과 다른 늦은 결과는 현재 상태에 반영하지 않는다.
- 배우자가 함께 화면을 보는 요구는 두 언어 표시로 반영한다. 배우자라는 이유만으로 별도 계정에 다른 이용자의 조회·수정·승인 권한을 부여하지 않는다.
- 아래 우선순위는 검토안이다. `user-flows.md`는 아직 빈 양식이므로 흐름 담당자와 맞춰야 한다. 원래 03의 `안내 검토 대기`를 이 문서의 `자동 점검중`·`담당자 승인 대기`와 같은 상태로 사용하지 않는다.

| 스토리 | 내용 | 기존 5-2 기능 | 수정 제안서 Ⅳ-11 기능 | 우선순위 |
| --- | --- | --- | --- | --- |
| US-01 | 상황 설명·준비 건 생성·모의 PDF 추가 | F-01 | F-01 | 필수 |

| US-04 | 담당자 승인·반려·두 언어 결과 조회 | F-04 | F-04·F-05 | 필수 |
| US-05 | 준비 상태 갱신·확인 요청 | F-05 | F-06 | 필수 |

## US-01 상황을 설명하고 본인 준비 건에 모의 PDF 추가하기

**이용자로서, 체류기간 연장 상황을 설명하고 준비한 서류를 본인 건에 추가하고 싶다. 내 상황과 서류에 필요한 주의점·추가 준비물을 안내받기 위해서다.**

- 우선순위: 필수
- 관련 기능: 기존 5-2 F-01 / 수정 제안서 Ⅳ-11 F-01
- 경로: 정상
- 관련 상태 전이: 시작 → 준비중
- LLM 관여: 아니오 (입력·문서 연결 단계)
- 관련 이슈: 다음 주에 채움
- 근거: 수정 제안서 Ⅰ-3·Ⅳ-11 F-01, 미팅 피드백 10·11, 기존 5-2 F-01.

### 인수 조건

- [ ] (정상) 이용자가 지원 유형·언어·상황 설명을 입력해 생성하면 본인 소유 준비 건 1개가 생기고 상태는 `준비중`으로 표시된다. 관할 관서를 아는 경우 해당 건에 함께 기록할 수 있다.
- [ ] (정상) 본인 건에 텍스트를 처리할 수 있는 모의 PDF를 추가하면 해당 서류가 그 건에 연결되고, 다시 조회했을 때 상황·유형·언어·관서와 추가한 서류를 구분해 확인할 수 있다.
- [ ] (실패·거절) 상황 설명이 비어 있거나 유형·언어가 지원 목록 밖이면 생성을 거절한다. PDF가 아닌 자료를 추가하거나 문서 내용을 읽을 수 없으면 자동 점검을 시작하지 않고 파일 수정·담당자 확인이 필요한 사유를 표시한다.
- [ ] (실패·거절) 실제 서류 처리 정책이 확정되지 않은 데모에서는 모의 자료만 사용한다. 금지 식별정보가 확인된 자료는 LLM 점검으로 넘기지 않는다.
- [ ] (권한) 이용자 A는 이용자 B의 상황·서류를 목록·상세·문서 열람에서 조회하거나 수정할 수 없다. 건·문서 식별자를 직접 지정해도 같은 제한을 적용한다.

### 미확정

- 첫 외국어·관서와 대표 서류, 파일 크기·개수 제한, 스캔 PDF OCR 지원 여부.
- 실제 서류 동의·접근·저장·보관·삭제 정책과 배우자 별도 접근 권한은 운영 전 확인한다. 준비 건 생성 시 제공할 입력 템플릿은 미팅의 추가 확인 항목으로 남긴다.

## US-02 공통·관서별 공식 기준을 등록하고 변경 시 재점검하기

**지원 담당자로서, 공통 기준과 확인된 관서별 추가 요구를 출처·버전과 함께 관리하고 싶다. 해당 상황에 적용되는 기준으로 서류를 대조하기 위해서다.**

- 우선순위: 필수
- 관련 기능: 기존 5-2 F-02 / 수정 제안서 Ⅳ-11 F-02
- 경로: 정상 / 되돌림
- 관련 상태 전이: 자동 점검중·담당자 승인 대기·서류 준비중·준비 확인 요청·보완 요청 → 자동 점검중
- LLM 관여: 아니오 (기준 등록·무효화 처리, 재점검은 US-03)
- 관련 이슈: 다음 주에 채움
- 근거: 수정 제안서 Ⅳ-11 F-02·Ⅳ-12·Ⅶ-16 H3, 미팅 피드백 13·14, 기존 5-2 F-02.

### 인수 조건

- [ ] (정상) 담당자가 기준을 등록하면 공통/관서별 구분, 적용 절차, 해당 관서(관서별 기준인 경우), 공식 원문·기관·링크·확인일·버전이 함께 조회된다.
- [ ] (정상) 해당 관서의 추가 기준이 확인되어 있으면 공통 기준과 구분해 대조에 사용한다. 관서별 출처·최신 여부가 확인되지 않았으면 추가 요구를 만들어 넣지 않고 `관서 확인 필요`로 표시한다.
- [ ] (정상) 적용 기준이 바뀌면 위 진행 상태의 해당 건은 `자동 점검중`으로 재점검한다. 이전 점검 결과·승인·확인 요청은 무효화되고 이용자는 기준 변경과 재검토 필요 상태를 확인할 수 있다.
- [ ] (실패·거절) 필수 기준 정보가 누락되거나 관서별 항목의 적용 관서가 없으면 등록을 거절하고 기존 적용 기준을 유지한다. 이전 버전 결과나 뒤늦게 도착한 이전 점검 결과로 승인·완료를 처리하지 않는다.
- [ ] (권한) 담당자 권한이 없는 계정은 기준 등록·변경·적용을 실행할 수 없다. 이용자에게 기준 편집 권한이나 타인 건의 재점검 권한을 부여하지 않는다.

### 미확정

- 기준 자료·적용 조건·갱신 책임자·확인 주기, 관서 전화 확인의 기록 방식과 재확인 주기.
- 이미 완료된 건에 대한 기준 변경 안내, 같은 버전의 중복 등록 처리. 관서별 정보가 미확정이면 공통 기준에 대한 점검과 관서 확인 필요 표시를 구분한다.

## US-03 상황·PDF를 공식 기준과 자동 대조하기

**지원 담당자로서, 이용자의 상황과 PDF를 공통·관서별 기준과 대조한 결과를 받고 싶다. 부재 시간에도 주의점·누락 가능성·추가 확인 사항을 검토할 자료가 준비되도록 하기 위해서다.**

- 우선순위: 필수 (부재 중 점검을 함께 검토)
- 관련 기능: 기존 5-2 F-03 / 수정 제안서 Ⅳ-11 F-03·F-09
- 경로: 정상 / 점검 실패
- 관련 상태 전이: 준비중 → 자동 점검중 → 담당자 승인 대기
- LLM 관여: 예
- 관련 이슈: 다음 주에 채움
- 근거: 수정 제안서 Ⅳ-11 F-03·F-09·Ⅳ-12~13, 미팅 피드백 1·3~5·9~11·13·14, 기존 5-2 F-03.

### 인수 조건

- [ ] (정상) 유효한 상황 설명·처리 가능한 모의 PDF·등록된 기준이 있는 본인 건에서 점검을 시작하면 시스템이 `자동 점검중`으로 기록한다. 결과에는 사용한 상황·문서·기준 버전이 연결된다.
- [ ] (정상) 대조가 끝나면 적용 근거·출처·기준일, 문서에서 확인한 내용, 주의점·누락 가능성·기재 불일치·추가 준비 서류 후보·확인 필요 사항을 구분해 담당자에게 제공하고 `담당자 승인 대기`가 된다.
- [ ] (정상) 담당자가 부재하거나 로그인하지 않아도 허용된 점검은 수행한다. 결과를 내부에 저장하되 담당자 승인 전에는 승인 대기를 유지하고 이용자에게 분석 본문을 공개하지 않는다.
- [ ] (실패·거절) 입력 누락·문서 처리 불가·등록 기준 없음은 점검 시작을 거절하고 `준비중`을 유지한다. 점검 시작 뒤 생성 실패·근거 부족·불확실성이 생기면 실패 사유를 남기고 `담당자 승인 대기`로 보내며 승인 성공으로 표시하지 않는다.
- [ ] (실패·거절) 현재 상황·문서·기준 버전과 다른 결과 또는 취소된 건의 결과가 늦게 도착하면 현재 결과·상태를 갱신하지 않는다. 근거 없는 항목은 확정 서류나 법률 판단으로 제시하지 않는다.
- [ ] (권한) 본인 이용자도 미승인 분석 본문을 조회할 수 없으며, 다른 이용자는 입력 서류·분석·대조 근거에 접근할 수 없다. 담당자 부재를 이유로 이용자에게 승인 권한을 부여하지 않는다.
- [ ] (LLM 경계) 사람이 확인·승인하기 전에는 승인 여부와 준비 완료 상태가 바뀌지 않는다. `자동 점검중 → 담당자 승인 대기`는 시스템의 진행 기록이며 LLM 출력만으로 `서류 준비중`·`준비 확인 완료`로 바꾸지 않는다.
- [ ] (Ⅳ-13) LLM 요청에 실명·연락처·외국인등록번호·여권번호·주소, 처리 승인 범위 밖의 원본 PDF·민감정보를 포함하지 않는다. 허용된 비식별 내용만 사용하고 금지 정보가 발견되면 수정 전 전송을 차단한다. 운영 조건 확인 전 실제 서류는 처리하지 않는다.

### 미확정

- 구체 점검 항목·실패 분류·재시도 정책, 비식별화·금지 정보 검사 방식과 허용 오류 수준.
- 담당자 부재 중 결과의 최종 공개 범위·대체 승인 운영. 현재 검토안은 미승인 본문을 내부용으로 유지하며 자동 승인은 두지 않는다.

## US-04 분석 결과를 승인·반려하고 두 언어로 함께 보기

**이용자로서, 담당자가 확인한 분석 결과·보완 이유·추가 준비물을 한국어와 모국어로 함께 보고 싶다. 배우자와 같은 안내를 이해하고 다음 준비 행동을 정하기 위해서다.**

- 우선순위: 필수
- 관련 기능: 기존 5-2 F-04 / 수정 제안서 Ⅳ-11 F-04·F-05
- 경로: 정상 / 취소·반려
- 관련 상태 전이: 담당자 승인 대기 → 서류 준비중 / 준비중
- LLM 관여: 예 (분석·번역 초안의 사람 검토)
- 관련 이슈: 다음 주에 채움
- 근거: 수정 제안서 Ⅳ-11 F-04·F-05·Ⅳ-12~13, 미팅 피드백 1·3·12, 기존 5-2 F-04.

### 인수 조건

- [ ] (정상) 담당자는 `담당자 승인 대기` 건의 상황·모의 서류·적용 기준·출처·기준일과 분석 결과·확인 필요 사항을 함께 조회해 검토할 수 있다.
- [ ] (정상) 담당자가 현재 상황·문서·기준에 대한 분석을 검토해 승인하면 `서류 준비중`으로 바뀌며 승인자·시점·적용 버전을 남긴다. 본인 이용자는 승인된 결과·주의점·근거·추가 준비물을 한국어와 선택 모국어로 동시에 조회할 수 있다.
- [ ] (실패·거절) `담당자 승인 대기`가 아닌 건, 이전 입력·기준을 사용한 결과, 미해결 확인 필요 사항이 남은 결과는 승인을 거절한다. 두 언어의 설명 중 누락된 내용은 검토·수정 전 승인된 완성 안내로 공개하지 않는다.
- [ ] (권한) 담당자 권한이 없는 계정은 승인·반려를 실행할 수 없고 다른 이용자는 승인된 결과도 조회할 수 없다. 배우자의 별도 계정·대리 접근은 자동 허용하지 않는다.
- [ ] (취소·반려) 담당자가 분석 오류·자료 부족의 사유를 남겨 반려하면 `준비중`으로 돌아간다. 사유가 비어 있으면 반려를 거절한다. 초기 검토의 자료 보완은 이 경로로 처리하고, 최종 준비 확인 단계의 `보완 요청`과 구분한다.
- [ ] (LLM 경계) 모든 건의 분석·번역 초안은 사람이 확인·승인하기 전까지 미승인으로 유지한다. 두 언어 생성 완료나 담당자 부재만으로 승인·준비 완료를 처리하지 않는다.
- [ ] (Ⅳ-13) 검토 중 분석·번역 재생성을 요청해도 실명·연락처·외국인등록번호·여권번호·주소, 처리 승인 범위 밖의 원본 PDF·민감정보는 LLM에 보내지 않는다. 금지 정보가 있으면 전송을 차단하고 현재 검토 상태를 유지한다.

### 미확정

- 첫 외국어와 두 언어 의미를 검토할 담당자, 담당자 배정·부재 시 대체 승인자·대기 안내.
- 두 언어 병렬 화면의 상세 구성과 배우자 별도 계정·위임 권한. 공동 열람 요구만으로 공유 링크·대리 수정 기능을 추가하지 않는다.

## US-05 준비 상태를 갱신하고 확인 요청하기

**이용자로서, 승인된 주의점·추가 준비 안내에 따라 준비 상태를 갱신하고 담당자 확인을 요청하고 싶다. 내 상황과 서류를 반영한 준비가 끝났는지 확인받기 위해서다.**

- 우선순위: 필수
- 관련 기능: 기존 5-2 F-05 / 수정 제안서 Ⅳ-11 F-06
- 경로: 정상 / 입력 변경에 따른 재점검
- 관련 상태 전이: 서류 준비중 → 준비 확인 요청; 상황·서류 변경 시 자동 점검중 → 담당자 승인 대기 → 서류 준비중
- LLM 관여: 아니오 (입력 변경 후 재점검·승인은 US-03·US-04)
- 관련 이슈: 다음 주에 채움
- 근거: 수정 제안서 Ⅳ-11 F-06·Ⅶ-16의 최신 상황·서류·기준 일치 규칙, 기존 5-2 F-05.

### 인수 조건

- [ ] (정상) 본인 `서류 준비중` 건에서 승인된 분석·추가 준비 안내를 조회하고 항목별 준비 상태를 갱신하면 다시 열었을 때 변경한 준비 여부와 승인 기준 버전이 조회된다. 단순 체크를 서류 대조 기능의 대체물로 사용하지 않는다.
- [ ] (정상) 현재 상황·서류·기준과 승인 결과가 일치하는 건에서 확인을 요청하면 `준비 확인 요청`이 된다. 미준비 항목이 있어도 요청할 수 있고 담당자는 준비 여부를 구분해 조회할 수 있다.
- [ ] (정상) 상황 설명이나 PDF를 바꾸면 이전 분석·승인·확인 요청을 무효화하고 `자동 점검중`으로 재점검한다. 새 결과의 담당자 승인을 거친 뒤에만 다시 확인 요청할 수 있다. 준비 여부만 갱신하고 상황·서류가 같으면 이를 새 PDF 대조로 취급하지 않는다.
- [ ] (실패·거절) 승인 전이거나 상황·서류·기준 버전이 달라진 건의 이전 결과로 확인 요청하면 거절한다. 승인된 목록 밖의 항목을 수정하거나 완료·취소된 건에 준비 내용을 저장해도 거절하고 끝 상태를 유지한다.
- [ ] (권한) 다른 이용자는 이 건의 준비 상태·서류를 조회하거나 수정·확인 요청할 수 없다. 본인 이용자도 담당자 승인·보완 판정·준비 완료 처리를 실행할 수 없다.

### 미확정

- 준비 상태 입력 항목·화면, 중복 요청 방지 방식과 개별 확인 요청 철회 기능.
- 상황·서류 변경과 준비 여부 변경을 구분하는 입력 계약. 요청 철회와 US-07의 준비 건 전체 취소를 같은 기능으로 취급하지 않는다.

## US-06 보완하고 다시 요청해 준비 확인 완료받기

**이용자로서, 담당자가 남긴 부족 항목과 이유에 따라 보완·재요청하고 싶다. 최신 상황·서류·기준으로 준비 확인을 마치기 위해서다.**

- 우선순위: 필수
- 관련 기능: 기존 5-2 F-06 / 수정 제안서 Ⅳ-11 F-07
- 경로: 정상 / 보완·되돌림
- 관련 상태 전이: 준비 확인 요청 → 보완 요청 → 서류 준비중 → 준비 확인 요청 → 준비 확인 완료 (상황·서류 변경 시 US-03·US-04 재점검·재승인 경유)
- LLM 관여: 아니오 (보완 판정·최종 완료는 담당자)
- 관련 이슈: 다음 주에 채움
- 근거: 수정 제안서 Ⅳ-11 F-07·Ⅳ-12·Ⅶ-16, 기존 5-2 F-06.

### 인수 조건

- [ ] (정상) 담당자가 `준비 확인 요청` 건의 부족 항목과 이유를 남기면 `보완 요청`이 되고 본인 이용자가 대상 항목·사유를 조회할 수 있다.
- [ ] (정상) 본인 이용자가 수정을 시작하면 `서류 준비중`이 되고 보완·재요청할 수 있다. 상황·PDF 내용이 바뀌면 US-03·US-04의 재점검·재승인을 거치며, 이전 보완 사유는 이력에 남는다.
- [ ] (정상) 담당자가 최신 상황·서류·기준과 승인 결과의 일치, 미해결 보완·확인 필요 사항 없음을 확인하고 완료하면 `준비 확인 완료`가 된다. 화면에는 실제 민원 접수·허가 완료를 뜻하지 않는다고 표시한다.
- [ ] (실패·거절) 대상 항목·사유가 없는 보완 요청, 미해결 보완·확인 필요 사항이 있거나 이전 입력·기준에 대한 완료 요청은 거절한다. 완료·취소된 건의 보완 저장·재요청도 거절한다.
- [ ] (권한) 이용자는 담당자의 보완 판정·준비 완료를 실행할 수 없고 다른 이용자는 이 건의 보완 사유·서류를 조회·수정할 수 없다.
- [ ] (보완·되돌림) 담당자만 `준비 확인 요청 → 보완 요청`을, 본인 이용자만 수정 시작에 따른 `보완 요청 → 서류 준비중`을 처리한다. 자동 점검 결과만으로 보완 해소·최종 완료를 처리하지 않는다.

### 미확정

- 보완 항목의 해결 확인 방법·확인 담당자, 실제 대표 서류별 최종 확인 항목.
- 준비 확인 범위와 법적 판단의 구분을 운영 담당자에게 확인한다. 담당자 모의 계정으로 시연한 결과를 실제 기관 승인·참여 확보로 표현하지 않는다.

## US-07 기준·검토 이력을 보고 본인 진행 건 취소하기

**이용자로서, 적용 기준과 점검·승인·보완 이력을 확인하고 진행 중인 본인 건을 취소하고 싶다. 현재 안내가 어떤 자료로 검토됐는지와 중단한 건을 구분하기 위해서다.**

- 우선순위: 필수
- 관련 기능: 기존 5-2 F-07 / 수정 제안서 Ⅳ-11 F-08
- 경로: 취소·반려
- 관련 상태 전이: 준비중·자동 점검중·담당자 승인 대기·서류 준비중·준비 확인 요청·보완 요청 → 취소 완료
- LLM 관여: 아니오
- 관련 이슈: 다음 주에 채움
- 근거: 수정 제안서 Ⅳ-11 F-08·Ⅳ-12, 기존 5-2 F-07.

### 인수 조건

- [ ] (정상) 담당자는 적용 상황·문서·기준 버전과 자동 점검·승인·반려·보완 이력을 구분해 조회할 수 있다. 본인 이용자에게는 미승인 분석 본문을 제외한 진행 이력과 승인된 안내 이력을 표시한다.
- [ ] (정상) 본인 이용자가 진행 건 취소를 확정하면 `취소 완료`가 되고 처리 시점·처리자 역할과 취소 이력이 남는다. 다시 조회해도 같은 끝 상태와 허용된 기존 이력을 볼 수 있다.

- [ ] (권한) 이용자 A는 이용자 B의 이력·분석·서류를 조회하거나 B의 건을 취소할 수 없다. 건·문서 식별자를 직접 지정해도 같은 제한을 적용한다.
- [ ] (취소·반려) 본인 이용자만 위 진행 중 여섯 상태의 건을 `취소 완료`로 바꿀 수 있다. 취소는 실제 서류 삭제나 외부기관 민원 취소를 뜻하지 않는다.

### 미확정

- 이력·원본·분석본의 접근 범위·보관 기간과 데이터 삭제 요청 처리.
- 취소 후 외부 알림 발송 억제·재시도 종료 방식. 업무상 취소와 자료 삭제를 구분하고 무기한 보관을 전제로 하지 않는다.

## US-08 동의한 채널로 대기·보완 알림 받기

- LLM 관여: 아니오
- 관련 이슈: 다음 주에 채움

- [ ] (정상) 본인 이용자가 알림에서 건을 열면 접근 권한을 확인하고 현재 상태·열람 허용 정보를 표시한다. 상태가 발송 시점과 달라졌으면 현재 상태를 표시한다.

## 합류·다른 문서 연결 확인

- 정상 데모는 위 여섯 상태이며 `user-flows.md` 담당자가 이 흐름과 US 번호를 반영·검토해야 한다. 취소·반려 연결은 필수 US-04(반려)·US-07(취소)이다.
- MVP 포함 표는 필수 검토안 US-01~US-07과 대조하고, 외부 알림 US-08은 선택으로 구분한다. 다른 팀원의 포함·제외 결정이나 교차 검토를 수행한 것으로 기록하지 않는다.
- 기존 03·5-2에는 이전 상태·기능 정의가 남아 있다. 이 백로그에서는 수정 제안서의 업무 흐름을 사용하며 위 대응표로 기존 ID를 추적한다. 해당 원본과 `mvp-scope.md` 비교 표·개인 기록의 이전 설명은 각 담당자가 최신 백로그 기준으로 다시 대조해야 한다.
- `[근거 없음]` 로그인·회원가입·마이페이지의 별도 화면, 배우자 자동 위임·공유 링크, 지원 범위 밖 체류 유형은 추가하지 않았다. 기존 본인 건 접근·담당자 권한은 유지한다.
- 법률 상담 탐색안 A의 쟁점 분류·긴급 연계·7일 미응답 종료를 이 준비 건의 기능으로 가져오지 않는다. 서류 진위 판정·허가 가능성 단정·외부기관 자동 전송도 이 백로그의 기능이 아니다.
