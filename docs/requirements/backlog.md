## US-01 상황 설명과 서류로 준비 건 만들기

**이용자로서, 내 상황을 설명하고 가진 서류를 올려 준비 건을 만들고 싶다. 왜냐하면 어떤 서류가 필요한지 고르는 데 가장 시간이 많이 들기 때문이다(피드백 10·11).**

- 우선순위: 필수
- 관련 기능: F-01
- 경로: 정상
- 관련 상태 전이: (시작) → 준비중
- LLM 관여: 아니오
- 관련 이슈: (다음 주에 채움)

### 인수 조건
- [ ] (정상) 이용자가 지원 유형 F-6-1, 상황 설명 1자 이상 1,000자 이하, PDF 파일 1~5개(각 10MB 이하)를 제출하면 준비 건이 1개 생성되고 상태는 `준비중`, 소유자는 제출한 이용자다.
- [ ] (정상) 생성 직후 이용자의 준비 건 목록에 새 건이 생성 일시와 함께 1줄 추가된다.
- [ ] (실패·거절) PDF가 아닌 파일(확장자 또는 파일 시그니처가 PDF가 아님), 10MB 초과 파일, 6개 이상 파일, 빈 상황 설명, F-6-1 외 유형 중 하나라도 있으면 준비 건을 만들지 않고 해당 항목과 거절 사유를 표시한다.
- [ ] (권한) 다른 이용자와 로그인하지 않은 사용자는 이 준비 건을 목록·상세에서 볼 수 없고, 상세 주소로 직접 요청하면 403(로그인 안 함은 401)을 받는다.

### 미확정
- 파일 크기·개수 상한(10MB, 5개)은 팀 설계값이다. 클라이언트 확인 전.
- 관할 관서 입력 여부는 관서별 기준 범위를 정한 뒤 추가한다.

## US-02 등록된 기준으로 서류 자동 점검하기

**지원 담당자로서, 담당자가 없는 시간에도 서류가 기준과 대조되어 있기를 바란다. 왜냐하면 모든 건을 직접 처음부터 대조하면 승인이 늦어지기 때문이다(피드백 3·4·9).**

- 우선순위: 필수
- 관련 기능: F-03, F-09
- 경로: 정상
- 관련 상태 전이: 준비중 → 자동 점검중 → 담당자 승인 대기
- LLM 관여: 예
- 관련 이슈: (다음 주에 채움)

### 인수 조건
- [ ] (정상) 준비중인 건의 상황 설명과 PDF 텍스트에 식별정보가 없으면 시스템이 상태를 `자동 점검중`으로 바꾸고 LLM 분석을 요청한다.
- [ ] (정상) LLM 분석이 끝나면 결과(주의점, 누락 가능성, 추가 준비 서류 후보, 각 항목의 근거 기준 ID·출처·기준일)를 저장하고 상태를 `담당자 승인 대기`로 바꾼다. 근거 기준 ID가 없는 항목은 "확인 필요"로 표시된다.
- [ ] (실패·거절) 상황 설명이나 PDF 텍스트에서 식별정보 패턴이 1개 이상 발견되면 LLM을 호출하지 않고 상태를 `준비중`으로 유지하며, 발견된 위치(파일명·페이지 또는 상황 설명)와 수정 안내를 이용자에게 표시한다.
- [ ] (실패·거절) PDF에서 텍스트를 추출하지 못하거나(스캔 PDF 포함) LLM 호출이 오류·60초 초과로 끝나면, 실패 사유를 결과에 기록하고 상태를 `담당자 승인 대기`로 바꾼다. 이때 결과에 "자동 점검 실패"가 표시되고 승인으로 처리되지 않는다.
- [ ] (권한) 자동 점검 결과는 담당자만 조회할 수 있다. 이용자와 다른 이용자가 결과를 요청하면 403을 받고, 이용자 화면에는 "담당자 검토 중"만 표시된다.
- [ ] (LLM) 자동 점검이 끝나도 상태는 `담당자 승인 대기`까지만 바뀐다. LLM 응답의 내용과 관계없이 시스템이 `서류 준비중`·`준비 확인 완료`로 바꾸는 경로가 없다.
- [ ] (LLM) LLM 요청 본문에 식별정보 패턴, 이용자 계정 ID·이메일, PDF 원본 파일(바이너리)이 들어가지 않는다. 보내는 것은 마스킹 검사를 통과한 상황 설명, PDF 추출 텍스트, 지원 유형, 등록된 기준 본문·출처·기준일뿐이다(제안서 Ⅳ-13).

### 미확정
- LLM 시간 제한 60초는 팀 설계값이다.
- 자동 점검 결과만으로 이용자가 다음 단계로 갈 수 있는 예외가 있는지 클라이언트에게 확인 전(client-meeting-1 다음 질문). 확인 전에는 예외 없음으로 구현한다.

## US-03 담당자가 분석 결과를 승인해 두 언어로 공개하기

**지원 담당자로서, 자동 점검 결과와 근거를 확인한 뒤 승인해 이용자에게 공개하고 싶다. 왜냐하면 모든 준비 건은 담당자 승인이 필요하기 때문이다(피드백 1·12).**

- 우선순위: 필수
- 관련 기능: F-04, F-05
- 경로: 정상
- 관련 상태 전이: 담당자 승인 대기 → 서류 준비중
- LLM 관여: 예 (승인 대상이 LLM 결과)
- 관련 이슈: (다음 주에 채움)

### 인수 조건
- [ ] (정상) 담당자가 `담당자 승인 대기` 건을 승인하면 상태가 `서류 준비중`이 되고, 승인자 ID·승인 일시·적용 기준 버전이 이력에 기록된다.
- [ ] (정상) 승인 후 이용자 화면에 승인된 항목이 한국어와 이용자가 고른 모국어로 한 화면에 나란히 표시되고, 항목마다 근거 출처와 기준일이 보인다.
- [ ] (정상) 담당자가 승인 전에 항목을 수정·삭제하면 이용자에게는 수정된 내용만 공개되고, 수정 전 LLM 원문은 이용자 화면에 나오지 않는다.
- [ ] (실패·거절) 결과에 "자동 점검 실패" 또는 "확인 필요" 항목이 남아 있으면 승인 버튼이 비활성화되고, 승인 요청을 보내도 상태가 바뀌지 않는다. 담당자가 해당 항목을 수정·삭제해야 승인할 수 있다.
- [ ] (실패·거절) `담당자 승인 대기`가 아닌 상태의 건에 승인을 요청하면 거절되고 상태가 바뀌지 않는다.
- [ ] (권한) 이용자와 다른 이용자는 승인 기능을 실행할 수 없다(요청 시 403, 상태 불변).
- [ ] (LLM) 승인 전에는 이용자가 상세 화면·API 어디에서도 분석 결과를 받을 수 없다.
- [ ] (LLM) 모국어 번역에 LLM을 쓰는 경우에도 번역 요청에 식별정보 패턴과 계정 정보가 들어가지 않는다(제안서 Ⅳ-13).

### 미확정
- 첫 데모의 모국어 1개는 미정(H2). 번역을 LLM으로 만들지, 담당자가 입력할지 미정.

## US-04 담당자가 분석 결과를 반려하기

**지원 담당자로서, 분석이 틀렸거나 자료가 부족하면 이유와 함께 반려하고 싶다. 왜냐하면 잘못된 분석이 이용자에게 확정 안내처럼 나가면 안 되기 때문이다.**

- 우선순위: 필수
- 관련 기능: F-04
- 경로: 취소·반려
- 관련 상태 전이: 담당자 승인 대기 → 준비중
- LLM 관여: 예 (반려 대상이 LLM 결과)
- 관련 이슈: (다음 주에 채움)

### 인수 조건
- [ ] (정상) 담당자가 반려 사유(1자 이상)를 입력해 반려하면 상태가 `준비중`이 되고, 반려자 ID·일시·사유가 이력에 기록된다.
- [ ] (정상) 반려 후 이용자 화면에 반려 사유가 표시되고, 이용자가 상황 설명·PDF를 수정해 다시 제출하면 US-02의 자동 점검이 새로 시작된다.
- [ ] (실패·거절) 반려 사유가 비어 있으면 반려되지 않고 상태가 `담당자 승인 대기`로 유지된다.
- [ ] (권한) 이용자와 다른 이용자는 반려 기능을 실행할 수 없다(요청 시 403, 상태 불변). 반려 사유는 해당 건의 이용자와 담당자만 볼 수 있다.
- [ ] (취소·반려) 상태를 바꾸는 사람은 담당자뿐이며, 조건은 `담당자 승인 대기` 상태와 사유 입력이다. 결과 상태는 항상 `준비중`이다.
- [ ] (LLM) 반려된 분석 결과는 이용자에게 공개되지 않는다.
- [ ] (LLM) 반려 사유는 LLM에 보내지 않는다. 담당자가 사유에 식별정보를 적을 수 있기 때문이다(제안서 Ⅳ-13).

### 미확정
- 없음

## US-05 준비 상태를 체크하고 확인 요청하기

**이용자로서, 안내된 주의점과 추가 서류에 따라 준비 상태를 갱신하고 확인을 요청하고 싶다. 왜냐하면 상황·서류 대조 결과에서 부족했던 준비를 마쳤는지 확인받고 싶기 때문이다.**

- 우선순위: 필수
- 관련 기능: F-06
- 경로: 정상
- 관련 상태 전이: 서류 준비중 → 준비 확인 요청
- LLM 관여: 아니오
- 관련 이슈: (다음 주에 채움)

### 인수 조건
- [ ] (정상) `서류 준비중` 건에서 이용자가 승인된 항목마다 "준비함/아직" 중 하나를 고르고 확인 요청하면 상태가 `준비 확인 요청`이 되고 요청 일시가 기록된다.
- [ ] (정상) "아직"인 항목이 있어도 확인 요청은 접수되고, 담당자 화면에 "아직" 항목 수가 표시된다.
- [ ] (실패·거절) 하나라도 선택하지 않은 항목이 있으면 요청이 거절되고 미선택 항목이 표시된다. 상태는 `서류 준비중`으로 유지된다.
- [ ] (실패·거절) `서류 준비중`이 아닌 건에서 확인 요청하면 거절되고 상태·요청 일시·준비 내용이 바뀌지 않는다.
- [ ] (실패·거절) 해당 건의 승인 목록에 없는 항목 ID, 다른 건의 항목 ID 또는 "준비함/아직" 외 값을 보내면 전체 요청을 거절하고 저장된 준비 내용을 바꾸지 않는다.
- [ ] (권한) 본인 이용자만 이 건의 준비 내용을 변경·확인 요청할 수 있다. 다른 이용자·담당자는 403, 미인증 요청은 401을 받고 상태·준비 내용이 바뀌지 않는다.

### 미확정
- 체크와 함께 추가 PDF를 올릴 수 있는지 미정.

## US-06 담당자가 보완 요청하고 이용자가 다시 준비하기

**지원 담당자로서, 부족한 항목과 이유를 지정해 보완을 요청하고 싶다. 왜냐하면 부족한 상태로 완료 처리하면 이용자가 잘못 준비하기 때문이다.**

- 우선순위: 필수
- 관련 기능: F-07
- 경로: 취소·반려
- 관련 상태 전이: 준비 확인 요청 → 보완 요청 → 서류 준비중
- LLM 관여: 아니오
- 관련 이슈: (다음 주에 채움)

### 인수 조건
- [ ] (정상) `준비 확인 요청` 건에서 담당자가 해당 건의 승인된 항목 중 1개 이상을 고르고 공백을 제거한 이유(1자 이상)를 항목마다 적어 보완 요청하면 상태가 `보완 요청`이 되고, 이용자 화면에 해당 항목과 이유가 표시된다. 요청자·일시·항목·사유가 이력에 기록된다.
- [ ] (정상) `보완 요청` 건에서 본인 이용자가 "수정 시작"을 누르면 상태가 `서류 준비중`이 되고, 보완 항목은 "아직"으로 초기화되며 나머지 항목은 유지된다. 보완 사유·이력은 삭제하지 않고 이후 US-05로 다시 확인 요청할 수 있다.
- [ ] (실패·거절) 항목을 고르지 않았거나 이유가 비었거나 공백뿐인 항목, 해당 건의 승인 목록에 없는 항목 ID 중 하나라도 있으면 전체 보완 요청을 거절하고 상태·항목·이력을 바꾸지 않는다.
- [ ] (실패·거절) `준비 확인 요청`이 아닌 상태에서 보완 요청하거나 `보완 요청`이 아닌 상태에서 "수정 시작"을 요청하면 거절되고 현재 상태·준비 내용은 바뀌지 않는다.
- [ ] (권한) 이용자는 보완 요청을 만들 수 없고, 다른 이용자·담당자는 "수정 시작"을 대신 실행할 수 없다(각각 403, 미인증은 401). 보완 사유는 해당 건의 이용자·담당자만 조회할 수 있다.
- [ ] (취소·반려) `준비 확인 요청` → `보완 요청`은 담당자만, `보완 요청` → `서류 준비중`은 해당 건의 이용자만 바꾼다. 미해결 보완 항목이 1개라도 있으면 US-07의 완료가 거절된다.
- [ ] (정상) 보완 항목의 "준비함" 선택만으로 미해결 사유를 자동 해제하지 않는다. US-05 재요청 후 담당자가 각 보완 항목의 처리 결과를 기록해야 해결된 것으로 판정한다. 이 판정은 LLM이 수행하지 않는다.

## US-07 담당자가 준비 확인 완료하기

**지원 담당자로서, 기준을 다 갖춘 건을 준비 확인 완료로 처리하고 싶다. 왜냐하면 이용자가 준비가 끝났는지 알 수 있어야 하기 때문이다.**

- 우선순위: 필수
- 관련 기능: F-07
- 경로: 정상
- 관련 상태 전이: 준비 확인 요청 → 준비 확인 완료
- LLM 관여: 아니오
- 관련 이슈: (다음 주에 채움)

### 인수 조건
- [ ] (정상) `준비 확인 요청` 건의 적용 기준 버전이 현재 등록된 기준 버전과 같고, 담당자가 처리 결과를 기록해 미해결 보완 항목이 0개이며, 모든 승인 항목이 "준비함"이면 담당자가 완료할 수 있고 상태가 `준비 확인 완료`가 된다. 완료자 ID·완료 일시·적용 기준 버전이 이력에 기록된다.
- [ ] (정상) 완료 화면에 "민원 접수나 체류기간 연장 허가가 아닙니다" 문구가 한국어와 이용자 모국어로 표시된다.
- [ ] (실패·거절) 기준 버전이 다르거나, 미해결 보완 항목이 있거나, "아직" 항목이 있으면 완료가 거절되고 거절 사유가 담당자 화면에 표시된다. 상태는 `준비 확인 요청`으로 유지된다.
- [ ] (실패·거절) `준비 확인 요청`이 아닌 상태에서 완료 요청을 보내면 거절된다. `준비 확인 완료` 건은 체크·첨부·상태를 바꿀 수 없고 재완료도 거절되어 기존 완료 일시·이력은 바뀌지 않는다.
- [ ] (권한) 이용자와 다른 이용자는 완료 기능을 실행할 수 없고(403), 미인증 요청은 401을 받는다. 화면 버튼 없이 직접 요청해도 상태·완료 이력이 바뀌지 않는다.

## US-08 이용자가 진행 중인 준비 건 취소하기

**이용자로서, 더 진행하지 않을 준비 건을 취소하고 싶다. 왜냐하면 다른 유형으로 다시 준비하거나 준비를 멈출 수 있어야 하기 때문이다.**

- 우선순위: 필수
- 관련 기능: F-08
- 경로: 취소·반려
- 관련 상태 전이: 준비중 / 자동 점검중 / 담당자 승인 대기 / 서류 준비중 / 준비 확인 요청 / 보완 요청 → 취소 완료
- LLM 관여: 아니오
- 관련 이슈: (다음 주에 채움)

### 인수 조건
- [ ] (정상) 진행 중 6개 상태 중 하나인 본인 건을 이용자가 취소 확인 후 취소하면 상태가 `취소 완료`가 되고, 취소 일시와 취소 전 상태가 이력에 기록된다.
- [ ] (정상) `자동 점검중`에 취소하면 이후 도착한 LLM 성공·오류 응답 모두 분석 결과로 저장·공개되지 않고 상태는 `취소 완료`로 유지된다. 취소가 모델 호출 자체의 중단이나 PDF 즉시 삭제를 보장하는 것은 아니다.
- [ ] (실패·거절) `준비 확인 완료`나 `취소 완료` 건은 취소할 수 없고 요청이 거절된다.
- [ ] (실패·거절) `취소 완료` 건은 수정·확인 요청·승인·반려·보완·완료가 모두 거절되고 기존 취소 이력은 바뀌지 않는다. 이용자는 새 준비 건을 만들어야 한다.
- [ ] (실패·거절) 취소 확인 창에서 돌아가면 취소 요청을 보내지 않고 상태·이력을 유지한다. 취소와 승인 요청이 겹쳐도 취소 완료 후 승인·자동 점검 결과가 도착해 건을 다시 진행 상태로 바꾸지 못한다.
- [ ] (권한) 다른 이용자와 담당자는 이 건을 취소할 수 없다(403, 미인증은 401). 직접 요청해도 상태·취소 이력이 바뀌지 않는다.
- [ ] (취소·반려) 상태를 바꾸는 사람은 해당 건의 이용자뿐이며, 조건은 진행 중 상태다. 결과 상태는 항상 `취소 완료`(끝 상태)다.

### 미확정
- 취소된 건의 PDF 보관 기간·삭제 시점(H4, 클라이언트 질문 7·10).
