# 핵심 사용자 흐름

> **저장 위치:** `docs/requirements/user-flows.md`

> 첫 데모에서 보여줄 흐름을 **하나만** 정합니다. 어제 그린 상태 전이(`docs/domain/03-rules-states-llm.md` 3-2)를 **처음부터 끝까지 한 번 지나가는** 정상 경로여야 합니다. 이 흐름이 첫 데모(3주차)에서 보여줄 그 흐름입니다.

- 작성일: 2026-10-26
- 기준: 제안서 작업본 Ⅳ-12와 백로그의 현재 흐름을 따른다. 2026-10-27 도메인 문서 03 3-2의 선정 B 상태도·L4도 같은 흐름으로 갱신했다. 미팅 전 후보 비교·가설은 과거 기록으로 구분한다.

## 연결된 상태 전이
03-rules-states-llm.md의 핵심 대상: **절차 준비 건** (선정 주제 B, 제안서 v2 Ⅳ-12)
지나가는 상태: 준비중 → 자동 점검중 → 담당자 승인 대기 → 서류 준비중 → 준비 확인 요청 → 준비 확인 완료 (6개)

## 첫 데모에서 보여줄 흐름 (1개)

데모 조건: 모의 계정 2개(이용자 1, 지원 담당자 1), F-6-1 체류기간 연장 1유형, 가상 상황 설명과 식별정보가 없는 모의 PDF 서류, 담당자가 미리 등록한 공통 기준 1개 버전.

| 순서 | 누가 | 무엇을 하는가 | 이때 상태 | LLM 관여 |
| --- | --- | --- | --- | --- |
| 1 | 이용자 | 지원 유형 F-6-1을 고르고 상황을 설명한 뒤 모의 PDF 서류를 올려 준비 건을 만든다 | (시작) → 준비중 | 아니오 |
| 2 | 시스템 | 입력 형식과 식별정보 포함 여부를 검사하고 통과하면 자동 점검을 시작한다 | 준비중 → 자동 점검중 | 아니오 (규칙 검사) |
| 3 | 시스템 | 등록된 기준과 서류를 대조해 주의점·누락 가능성·추가 준비 서류 후보·근거 출처를 담당자용 결과로 저장한다 | 자동 점검중 → 담당자 승인 대기 | 예 (분석 초안 생성) |
| 4 | 지원 담당자 | 서류, 기준 출처·기준일, 분석 결과를 확인하고 승인한다. 승인된 결과가 한국어와 배우자 모국어로 이용자에게 공개된다 | 담당자 승인 대기 → 서류 준비중 | 예 (승인 대상인 초안. 상태는 담당자가 바꿈) |
| 5 | 이용자 | 공개된 주의점과 추가 서류를 보고 준비 항목을 체크한 뒤 확인을 요청한다 | 서류 준비중 → 준비 확인 요청 | 아니오 |
| 6 | 지원 담당자 | 승인 결과가 현재 기준 버전과 같고, 미해결 보완·확인 필요 항목이 없고, 모든 항목이 "준비함"인지 확인해 완료 처리한다. 화면에 "민원 접수·허가 완료가 아님"을 표시한다 | 준비 확인 요청 → 준비 확인 완료 | 아니오 |

## 이 흐름에 포함하지 않은 경로

> 취소·반려·되돌림은 첫 데모 흐름에는 넣지 않습니다. 대신 **취소·반려는 `backlog.md`의 필수 스토리에서 다룹니다.**

| 경로 | 필수 스토리 | 누가·조건 | 상태 전이 / 정상 흐름 복귀 |
| --- | --- | --- | --- |
| 담당자 반려 | [US-04](backlog.md#us-04-담당자가-분석-결과를-반려하기) | 담당자가 승인 대기 건에 사유를 기록 | 담당자 승인 대기 → 준비중. 이용자가 자료를 고쳐 US-02로 재점검 |
| 보완·되돌림 | [US-06](backlog.md#us-06-담당자가-보완-요청하고-이용자가-다시-준비하기) | 담당자가 항목·사유를 지정하고 본인 이용자가 수정 시작 | 준비 확인 요청 → 보완 요청 → 서류 준비중. US-05 재요청 후 담당자가 보완 처리를 확인 |
| 이용자 취소 | [US-08](backlog.md#us-08-이용자가-진행-중인-준비-건-취소하기) | 본인 이용자가 진행 중 6개 상태에서 취소 확인 | 진행 중 상태 → 취소 완료. 끝 상태이며 재진행은 새 건으로 시작 |
- 기준·상황·서류 변경에 따른 재점검(각 진행 상태 → 자동 점검중)은 첫 데모 흐름에 넣지 않고, backlog.md 공통 조건과 US-02 인수 조건에서 다룬다
- 자동 점검 실패·근거 부족 경로는 US-02의 실패 인수 조건에서 다룬다
