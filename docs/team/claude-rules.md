# 팀 CLAUDE.md 규칙 합의 기록

> **저장 위치:** `docs/team/claude-rules.md`

> **사용 방법**
> 1. 각자 "Claude가 같은 말을 반복하게 만든 것", "팀이 같은 방식으로 해야 하는 것"을 **하나씩** 후보로 적습니다.
> 2. 후보마다 **어디에 적을지**부터 정합니다. 개인 / 팀 / 로컬. 판단 기준은 아래 3줄입니다.
> 3. **팀**으로 정한 것만 `CLAUDE.md`에 옮깁니다. 이 파일은 합의 기록이고, `CLAUDE.md`는 **짧게**(200줄 이하) 둡니다.
> 4. 개인 규칙과 팀 규칙이 **모순되지 않는지** 확인합니다. 모순되면 Claude가 아무거나 고릅니다.
> 5. 비밀 값(키·비밀번호)은 어디에도 적지 않습니다. 필요한 환경변수 **이름**만 적습니다.
> 6. `>`로 시작하는 안내 문장은 지워도 됩니다.

## 어디에 적을까 (판단 기준 3줄)

| 적을 것 | 위치 | git 공유 |
| --- | --- | --- |
| 내 취향 (응답 언어, 들여쓰기) | `~/.claude/CLAUDE.md` | 안 됨 |
| **우리 팀 규칙** (스택, 실행 명령, 폴더·커밋 규칙, 건드리면 안 되는 것) | `./CLAUDE.md` | **됨** |
| 내 컴퓨터 경로, 테스트용 주소 | `CLAUDE.local.md` | 안 됨 (git에서 제외) |

## 꼭 들어가야 할 것 (우리 과정의 원칙)

- [ ] 인수 조건은 사람이 쓴다. Claude가 고치지 않는다
- [ ] MVP 범위와 기술 스택은 Claude가 바꾸지 않는다
- [ ] 이미 낸 제안서(`docs/proposal/`)는 고치지 않는다
- [ ] 근거가 없으면 지어내지 않고 `[근거 없음]`이나 `미정`으로 쓴다
- [ ] `main`에 바로 커밋하지 않는다

## 막을 것 (→ `docs/decisions/permissions.md`로)

## 점검 (CLAUDE.md를 쓴 뒤)
- [ ] 서로 모순되는 규칙이 없다
- [ ] 지키는지 확인할 수 없는 모호한 문장이 없다
- [ ] 200줄 이하다. 긴 설명은 문서로 두고 `@`로 가져왔다
- [ ] `/memory`에서 팀 `CLAUDE.md`가 읽히는 것을 확인했다
- [ ] 아직 만들지 않은 실행·테스트 명령을 지어서 적지 않았다
