| 첫 커밋 이후에는 main에 바로 커밋하지 않는다. 모든 변경은 브랜치를 만들고 PR로 올린다 | **일부만.** 첫 커밋 이후 main 직접 커밋 13건. 10-12 용어 사전 팀원 입력 5건·설정 정리 2건·02 초안 1건, 10-13 개인 회고 3건, 10-20 일일 기록 1건, 10-26 배포 양식 배치 1건 | 고침 (제안) | **main 브랜치 보호를 켜서 PR 없이 push할 수 없게 한다.** 예외 없음(일일 기록·회고도 PR). 이유: 규칙만 있고 막는 장치가 없어 "작은 변경"마다 예외가 생겼다. 직접 커밋이 2주차(10-26)까지 이어졌다 |
| PR은 팀원 1명 이상이 승인하면 병합한다 (v2·제안서 PR은 작성자 제외 4명) | **아니오.** 병합된 PR 20건 모두 GitHub 승인(Approve) 0건. 작성자 본인이 병합한 PR 3건(#8·#16·#19). 제안서 PR 6건(#8·#9·#14·#15·#16·#17)도 승인 0건 | 고침 (제안) | **작성자가 아닌 1명이 GitHub에서 Approve해야 병합 버튼이 열리게 브랜치 보호에 "승인 1명 필수"를 건다. 작성자는 자기 PR을 병합하지 않는다.** 고객에게 내는 문서는 승인 2명. 이유: 말로 "봤다"는 확인이 남지 않았고, 4명 기준은 한 번도 지켜지지 않아 지킬 수 있는 숫자로 줄인다 |
| 표가 있는 단계 파일은 블록마다 정리 담당 1명이 고친다. 다른 사람은 카드를 쓰거나 PR에 댓글을 남긴다 | **일부만.** 카드·개인 회고는 사람별 파일로 지켜짐. 그러나 `draft.md`는 5명이 각자 PR로 고침(#8·#9 김태후, #14 여철준, #15 권길현, #16 이주환, #17 김민건). 02·03·topic-selection도 정리 담당 외 1명이 함께 고침(#7) | 고침 (제안) | **파일마다 그날의 정리 담당 1명을 PR 설명에 적는다. 다른 사람이 같은 파일을 고칠 때는 정리 담당을 리뷰어로 지정하고, 정리 담당의 PR이 열려 있으면 그 PR에 리뷰 제안(suggestion)으로 남긴다.** 이유: 1명만 고친다는 규칙은 제안서처럼 모두가 손대야 하는 문서에서 지켜지지 않았다. 고치는 사람을 막기보다 정리 담당이 반드시 보게 한다 |
